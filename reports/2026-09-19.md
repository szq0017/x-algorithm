- **① 「滞在時間ベースの別方式ランキング」という選択肢が、コードごと消えました（後述1）。今日いちばん重要な変更です。**

## 変更サマリ

1. **代替スコアリング方式「dwell-regret」とその出し分けゲートモデルが全面削除**（`ranking_scorer.rs` -477行、`value_model_gate.rs` -537行、関連パラメータ17件削除）。For You のスコア計算は従来の加重和方式に一本化された。
2. **Phoenix リトリーバルに「コールド投稿」専用データセット（`dataset_type=13`）の取得枠を新設**（既定 0 = オフ）。学習側のモデル書き出しも、データセット種別ごとに Top-K を出力する方式へ大改修。
3. **Under the Hood（透明性レポート）が「法的要請による国別非表示」を利用者に開示**（README に 9/18 付更新）。集計ジョブは対象理由を4種に限定し、画像系の理由を除外。
4. **可視性フィルタに新 gRPC エンドポイント `evaluate_tweets` を追加**し、TES への問い合わせを複合フェッチに統合。ハイドレーション失敗を `Failed` として呼び出し側に伝達する仕組みを導入。
5. **Grok の成人向けスパム動画検知が、いいね512以上の投稿で推論モードに切り替わる**ようになった。
6. 安全ラベル取得で、**同一投稿IDが重複して要求された際の無駄な再照会・誤失敗を修正**。

## 変更点ごとの詳細

### 1. 代替スコアリング方式「dwell-regret」の全面撤去

**メカニズム（コード根拠）**

- `home-mixer/scorers/value_model_gate.rs` が**ファイルごと削除**（537行）。`home-mixer/scorers/mod.rs` からも登録解除。これは「どのユーザーに新方式を出すか」をロジスティック回帰（フォロワー数・アクティブ日数・いいね頻度など19特徴量）で判定し、ヒステリシス帯付きで出し分けていたモデル。
- `home-mixer/scorers/ranking_scorer.rs`：`DwellRegretWeights` 構造体、`compute_dwell_regret_base_scores()`（候補群の平均に対する比を sigmoid 変調し滞在時間に乗算する計算）、`centered_ratio()`、`sigmoid()` をすべて削除。スコア分岐も削除され、**常に加重和 → `offset_score()` の経路のみ**になった（現 `:576-583` 相当）。
- `home-mixer/params/param.rs`：`ValueModelMode` に加え、`DwellRegretTemperature`／`DwellRegretDwellFloor`／`DwellRegretAlpha*`（7件）／`DwellRegretNeg*`（4件）／`DwellRegretGateWeights`／`DwellRegretGateBias`／`DwellRegretGateThreshold`／`DwellRegretGateHysteresisBand` の **計18パラメータを削除**。
- 方式名の記録は定数に置き換わり、常に固定値を送る：`pub(crate) const WEIGHTED_VALUE_MODEL_MODE: &str = "weighted";`（`ranking_scorer.rs:13`）、`value_model_mode: Some(WEIGHTED_VALUE_MODEL_MODE.to_string())`（`side_effects/reranking_kafka_side_effect.rs:87`）。
- 削除されたテストから、旧方式の設計値が確認できる（参考）：ネガティブ側の重みは `not_interested -10000`、`block_author -8000`、`mute_author -15000`、`report -60000`、温度 `10.0`、滞在時間の下限 `1.0` 秒。

**X ユーザー／クリエイターへの影響**

- **順位決定の枠組みが「確率×固定重みの加重和」に確定した**。公開されている `ScoringWeights` の重み値から順位を説明できる度合いが（少なくとも `RankingScorer` の範囲では）維持される。
- **「候補群の平均との相対比」で評価される方式が消えた**ことで、8/14 レポートで指摘した「エンゲージメント率が母集団平均からどれだけ乖離しているかが直接効く」というリスクは**当面消滅**した。
- **滞在時間（dwell）は引き続きシグナルの1つとして重みを持つ**（`cont_dwell_time_weight` 等は健在）。消えたのは「滞在時間を土台に据える別方式」であって、滞在時間そのものの評価ではない。
- なお `VMRanker`（外部価値モデルによる再ランキング）は今回**一切変更されていない**。「外から説明できない要素」の本丸はそちらに残っている。

### 4. 可視性フィルタ基盤の大規模リファクタと新エンドポイント

**メカニズム（コード根拠）**

- **新エンドポイント `evaluate_tweets`**（`visibility-filtering/evaluate_tweets.rs`、258行・新規）。`server.rs:55-60` で gRPC サービスに登録。対応する安全レベルは `FilterAll` / `TimelineHome` / `TimelineHomeRecommendations` の3つのみで、それ以外は `Unimplemented` を返す（`evaluate_tweets.rs:50-58`）。
- 結果は**投稿ごとに3値**で返る：`ActionThriftCompact`（判定できた）／`NotEvaluated`（引用文脈付きなど対象外）／`Failed`（判定不能）（`:85-104`）。判定できた場合のみ Thrift の `Action`（`Allow` または理由付き `Drop`）を返す。
- **新しい失敗の概念**：`EvaluationStatus { Evaluated, UnresolvedAuthor, Failed }`（`visibility-filtering/filter.rs:16-21`）。ハイドレーション（前提データの取得）が1つでも欠けた投稿は `Failed` になる（`hydration/mod.rs:256-272`）。判定条件は、本文データ欠落・著者情報が不完全・関係性照会失敗・複合フェッチ失敗・安全ラベル欠落・サブスク限定情報が不完全のいずれか。閲覧者情報の取得が不完全なら**全候補**が `Failed` 扱い（`:286-288`）。
- **TES（投稿情報サービス）への問い合わせを複合フェッチに統合**：新規 `hydration/tes_composite.rs`（607行）が `tweetypie/federated/tweetForVisibility.Tweet` を1回で取得し、著者ID・ヌルキャスト・NSFW（本人/管理者）・テイクダウン・メディア・コミュニティ投稿・編集情報・**サブスク限定の会話著者ID**をまとめて返す（`:16-29`）。
- これに伴い、**サブスク限定判定のための独立した TES 呼び出し（`get_exclusive_controls`）が廃止**（`hydration/exclusive_content_hydrator.rs`）。会話著者IDは複合フェッチの結果から `oneshot` チャネルで受け渡される（`hydration/mod.rs:182, 199-209`）。
- **「不完全」を型で表現**：`Completeness<V>`（`hydration/batch.rs:7-46`）。超フォロー照会が失敗した場合、従来は「超フォローしていない」と同義に潰れていたが、今後は `Incomplete` として区別される（`exclusive_content_hydrator.rs` の `Completeness::new(super_follows.is_some(), features)`）。
- ハイドレーション全体のタイムアウトは **390ms**（`hydration/mod.rs:37`）。クライアント側 `visibility-filtering-client/vf_client.rs:311-334` にバッチ分割・順序検証付きの `evaluate_tweets()` を追加。

**X ユーザー／クリエイターへの影響**

- **既存経路の挙動は変わらない。** `filter_tweets` エンドポイントの返す判定は従来どおりで、`status` は使われていない。
- **潜在的な改善：** サブスク限定（Super Follows）投稿について、社内照会が遅延・失敗したときに「購読していない」と誤断定される経路が、**型レベルで区別できるようになった**。呼び出し側が `Failed` を適切に扱えば、**購読者なのに限定投稿が見えないという誤りが減る**可能性がある。ただし本リポジトリの範囲では、それが実際に利用者体験に反映されるかは確認できない（**要確認**）。
- 問い合わせ回数が減ったことで、**判定が390msに間に合わずに失敗する確率は下がる方向**。表示の取りこぼし・誤った非表示が減る方向に働く。

### 5. Grok：成人向けスパム動画検知の「精読モード」

**メカニズム（コード根拠）**

- `grox/flows/ptos/constants.py:40`：`MEDIA_INJECTED_REASONING_FAV = 512` を新設。
- `grox/flows/ptos/task_safety_ptos_media_injected_adult_infrared_video_spam_detection.py:111`：`use_reasoning = post.get_fav_count() >= MEDIA_INJECTED_REASONING_FAV`。
- 該当する場合、システムプロンプトから**思考の制限を外し**（`:138` `_strip_thinking_restrictions(prompt)`）、アシスタント側の思考終了マーカーを**付けない**（`:156`）＝モデルが自由に推論過程を展開してから結論を出す。ログにも `use_reasoning` が記録される（`:118`）。
- 判定対象になる条件（動画付き・いいね64以上・未NSFW判定など）と、違反時の扱い（`SpamManipulatedMedia` / カテゴリ `Spam`）は**前回から変更なし**。

**X ユーザー／クリエイターへの影響**

- **影響は限定的だが方向性は重要。** 「**伸びた投稿ほど丁寧に審査する**」という二段構えが導入された。いいね512未満は従来どおりの即断モード、512以上は推論モード。

- 逆に、**スパム側が「伸びる前に稼ぎ切る」戦略を取る余地**は残る（512未満は簡易判定のまま）。

## 不確実な点（要確認）

- **dwell-regret 方式が本番でどの程度・どの期間・どの規模で試されたのか、そして撤去の理由**は公開コードからは一切分からない。「効果がなかった」「別の実装に移した」「実験が完了しただけ」のいずれも可能性がある。**特に、同等の機能が `VMRanker`（外部価値モデル）側に移管された可能性は否定できない**（`VMRanker` は今回未変更だが、外部モデルの中身は非公開）。
- `PhoenixColdStartMaxResults` の**本番での実設定値**。リポジトリの既定は `0` だが、フィーチャースイッチは外部設定で上書きされるため、**本番で 0 とは限らない**。
- `ForYouPhoenixRetrievalCold` が指す「コールド」の**具体的定義**（投稿からの経過時間か、エンゲージメント数か、著者の実績か）。学習側の `dataset_type=13` の中身はこのリポジトリには含まれていない。
- MoE 推論クラスタ `Experiment2Memy04` → `Experiment3Memy04` の**中身の差分**（モデル自体は非公開）。クラスタIDの切替は過去にもモデル更新を伴っていた可能性がある。
- **Under the Hood のレポートUIで、画像系理由（ヘイト画像・センシティブ画像）が別の形で開示されているかどうか。** 今回削除されたのは PCTD 集計ジョブ内の経路であり、別経路での開示は否定できない。
- `evaluate_tweets` の `Failed` を、**呼び出し側がどう扱うか**（再試行するのか、安全側に倒して非表示にするのか、表示するのか）。呼び出し側の実装は公開範囲外。**したがって「サブスク限定投稿の誤った非表示が減る」は設計上の期待であって、確定した改善ではない**。
- Grok の成人向けスパム動画検知フローが**本番で実際に稼働しているか**（9/18 レポートで指摘したとおり、参照動画バンドルの設定が未設定なら何も判定されない）。今回の推論モード追加は、稼働を前提とした調整に見えるが確証はない。
- いいね **512** という閾値がコード定数であること自体は確実だが、**この値が今後も維持されるか**は不明。
