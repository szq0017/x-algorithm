### 1. エンゲージメント誘導ラベルによるヘッド無効化が完成（既定OFF）

**メカニズム（コード根拠）**

昨日入った配管は「投稿の安全性ラベルを読んで、リプライ／共有／クリックの3種を `ineligible`（対象外）としてランカーへ渡す」ところまででした。

```

reply: labels.contains_key(&SafetyLabelType::PROMOTES_REPLIES),
share: labels.contains_key(&SafetyLabelType::PROMOTES_SHARES),
click: labels.contains_key(&SafetyLabelType::PROMOTES_CLICKS),
```

今日、受け取った側（VM ranker）の処理が入りました。

```rust
// vm-ranker/scoring/value_model.rs:214-232
fn exclude_ineligible_heads(candidate: &RankCandidate, scores: &mut PhoenixScores) -> [bool; 3] {
    ...
    if payload.reply_ineligible {
        scores.reply_score = None;

    if payload.share_ineligible {
        scores.share_score = None;
        scores.share_via_dm_score = None;

```

`None` がスコアにどう効くかは価値モデル本体で確定します。

```rust

fn apply(score: Option<f64>, weight: f64) -> f64 {
    score.unwrap_or(0.0) * weight
}
```

つまり **`None` は寄与 0.0**。減衰ではなく完全な除外です。制御スイッチは `rust_home_mixer_vm_ranker_exclude_ineligible_engagement_heads`（`vm-ranker/params.rs:328`、既定 `false`）。

対称性の確認もテストで担保されています（`vm-ranker/scoring/mod.rs:482`〜）。各ラベルについて、スコアが「全ヘッド合計 −（そのラベルに対応する寄与）」に 1e-12 の精度で一致し、スイッチOFFなら全ヘッド合計のままであることが検証されています。共有系は3ヘッド（`share` + `share_via_dm` + `share_via_copy_link`）がまとめて落ちます。

**Xユーザー/クリエイターへの影響**

- 「リプで教えて」「RTで拡散希望」「詳細はリンクから」といった**行動を直接要求する投稿**は、要求した行動の分だけスコアを稼げなくなります。
- 無効化は**種類ごとにピンポイント**です。リプライを煽った投稿は、いいね・滞在時間・動画視聴の分は普通に評価されます。全体にペナルティを掛けるのではなく「煽った分は数えない」設計です。
- リプライヘッドは他ヘッドより重みが大きく扱われています（上記テストでは係数4.0相当）。したがって**リプライ誘導の損失がもっとも大きい**と推定されます。
- 共有誘導は3ヘッド同時に落ちるため、合計の損失額としてはリプライに次ぐ規模になり得ます。
- ラベル取得は80msでタイムアウトし、失敗時は「ラベル無し」扱い（＝罰しない）です。また `experiment_payload` が空、またはデコードに失敗した場合も無効化は起きません（`value_model.rs:215`〜`:219`）。**誤爆方向には安全側**の実装です。
- 既定OFFのため、今日の時点で順位は変わりません。

### 8. Page-RL のスコア計算で動画品質視聴（VQV）の扱いが変更

**メカニズム（コード根拠）**

```python
# phoenix/xrex/models/page_rl.py:414, 432, 443
vqv_term = vqv_w * head(an.CLIENT_TWEET_VIDEO_QUALITY_VIEW)
...
raw_add = engage + vqv_term + dwell_term + not_dwelled * not_dwelled_p
...
time = 1.0 + jnp.maximum(dwell_term, 0.0) + jnp.maximum(vqv_term, 0.0)
```

従来 VQV は `engage`（エンゲージメントの和）の内側にありました。今日の変更で `engage` から外され、**加算モードでは独立項**、**乗算モードでは「時間」係数の一部**になりました。乗算モードのスコアは `skip × engage × time` の形なので、VQV が `time` に入ると**エンゲージメント見込みと掛け算で効く**ようになります。

重要な注意：**配信側の Rust 価値モデルは変わっていません。** `xai-value-model/scoring.rs` では VQV は依然として `engage_sum` の内側にあり、`time_factor` は滞在時間のみです（`fn engage_sum` / `fn time_factor`）。今日の `xai-value-model/scoring.rs` の差分はテストの追加（video_continuation を含むケース）だけで、本体のロジック変更はありません。

**Xユーザー/クリエイターへの影響**

- Page-RL は「ページ単位（1画面分）の並べ方」を学習・再並び替えする仕組みです。乗算モードでは、**動画品質視聴の見込みが高い投稿が、エンゲージメント見込みと掛け算で増幅される**方向になります。
- つまり**「見られそう、かつ反応されそうな動画」が一段強くなる**方向です。どちらか片方だけ高い投稿は従来ほど伸びません（掛け算なので片方が小さいと積も小さい）。
- ただし配信側の価値モデルと式がずれたため、**どちらが本番の最終順位を決めているかは公開コードから断定できません**（後述の要確認）。

- **シャドートラフィックの実験クラスタ `Experiment19Fou` の比率が 0.3 → 0 に**（`home-mixer/params/param.rs:104`）。シャドートラフィックは比較用の複製リクエストで**ユーザーに返される結果には影響しません**。1つの実験クラスタへの複製が止まった、という運用上の変更です。
