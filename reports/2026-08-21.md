## 非IT精通者向け・運用方法のまとめ（行動指針）

- **「For You」の投稿の上に、Grokが自動生成した“トレンド名”のラベルが付き始める下地ができた**。従来の「トピック」ラベル（例: テクノロジー）に加え、**AIトレンド名**（例: そのとき盛り上がっている出来事名）が投稿の見出しとして表示され、タップすると `x.com/i/trending/<ID>` のトレンドページに飛ぶ。**ただし既定はオフ**（`rust_home_mixer_enable_ai_trend_feedback_context` = false）。
- **ラベルが付くのは「1レスポンスあたり最大2件」の投稿だけ**で、しかも「その日のフィード内で最も多く出現した上位2トレンド」から**ランダムに1投稿ずつ**選ばれる。狙って付けさせることはほぼ不可能で、**ラベル取得を目的にトレンド便乗投稿を増やす価値は薄い**（付与はランキング順位ではなくランダム選択）。
- **ラベル対象は「リプライでも引用RTでもリポストでもない、単独のオリジナル投稿」のみ**。トレンドに触れるなら**引用RTやリプライではなく単独投稿**のほうがラベル露出の目があり、かつタップでトレンドページに送客される導線が付く（＝トレンド全体の閲覧が増え、間接的に露出機会が増えうる）。
- **「トピック」ラベルが付く投稿にはAIトレンドラベルは付かない**（トピック優先）。両方の候補になった場合はトピック名が表示される。
- **「フォロー中」タブとトピックタイムラインでは、このAIトレンドラベルは動かない**（For You など、フォロー外を含む面のみ）。
- **ランキングの重み（いいね・返信などの点数配分）の数値変更は今回もゼロ**。順位付けの体感が今日から変わる要素は本コミットには含まれない。
- **著者多様性（同じ人の連投を薄める仕組み）の“数え方”をモデルサーバ側の値に切り替えるスイッチが新設**されたが**既定オフ**。有効化されると「同じ著者が何回目か」の判定基準がホームミキサー内部の計算からPhoenix（ランキングモデル）側の計算に変わる。理論上、連投抑制の強さがわずかに変わりうる（要確認）。
- **安全性判定（成人向け・暴力的メディア・児童安全）の再チェックに使う新モデル Grok 4.6 の投入比率が 10% → 30% に引き上げ**。判定基準そのものは変わらないが、**同じ投稿でも判定にブレが出る余地が3倍**になった。高エンゲージ（いいね1024以上）の成人向け／暴力的メディア投稿の作者は、扱いが日によって変わる可能性を織り込むとよい。

## 変更サマリ (3–6行)

小規模差分（14ファイル）で、**ランキング重みの数値変更はゼロ**。実質の中身は4点: (1) home-mixer に **AIトレンド・フィードバックコンテキスト**の新ハイドレータが追加され、For You の投稿見出しに「Grok生成トレンド名＋トレンドページへのリンク」を出す配線が入った（既定オフ）。(2) 著者多様性・MPNスコアリングで使う **slate context を Phoenix が返した値に差し替えるスイッチ** `UseServedSlateContext` を新設（既定オフ）。(3) grox の安全性ポリシー分類で **Grok 4.6 内部モデルの投入比率を 0.1 → 0.3** に引き上げ、著者プロフィール画像をデータモデルに追加（プロンプト未使用）、LLMストリーミングに早期停止フックを追加。(4) Phoenix の `emb_table.rs` は **純粋なリファクタ**（Python束縛と本体ロジックの分離）で挙動不変。

### 2. 著者多様性・MPNスコアリングの slate context を「Phoenix が返した値」に切り替えるスイッチ

**メカニズム (コード根拠):**

- 新パラメータ `UseServedSlateContext`（`home-mixer/params/param.rs:246-251`, `rust_home_mixer_use_served_slate_context`, **既定 `false`**）。
- Phoenix のレスポンスから slate context を受け取る配線を追加（`home-mixer/scorers/phoenix_scorer.rs:110-112`）:
  ```rust
  served_slate_context: predictions
      .candidate_slate_context(&c.get_original_tweet_id())
      .map(Into::into),
  ```
  `home-mixer/models/candidate.rs:99-116` に `From<xai_recsys_proto::SlateContext>` 変換を追加。`PostCandidate.served_slate_context` フィールド新設（`candidate.rs:26`）。
- `home-mixer/scorers/ranking_scorer.rs:703-711` に `served_slate_contexts()` を追加。優先順位が3段になった（`:819-823` と `:889-893` の2か所、MPN 経路と通常経路の両方）:
  ```rust
  match Self::served_slate_contexts(query, candidates) {
      Some(served) => Some(served),
      None if query.has_cached_posts => Self::stored_slate_contexts(candidates),
      None => Some(Self::compute_slate_contexts(candidates, &weighted_scores)),
  }
  ```
  → **Phoenix提供値 > キャッシュ済み値 > ローカル再計算**。
- slate context の中身は `k`（同一著者が何番目か）、`pool_rank`、`pool_rank_gap`、`sid_k_l1..l3` / `sid_gap_l1..l3`（セマンティックID＝話題クラスタ単位の重複度）、`pre_diversity_score`（`candidate.rs:84-97`, 計算元は `ranking_scorer.rs:647-701`）。
- 著者多様性の乗数は `k` から算出される（`ranking_scorer.rs:717-728` → `diversity_multiplier(decay, floor, k)`）。`UseServedSlateContext` 有効時、`has_cached_posts == false` なら **スコアリングにも Phoenix 提供の `k` が使われる**（`:826-836`, `:896-906` の `Some(contexts) if !query.has_cached_posts => contexts`）。`has_cached_posts == true` の場合はスコアリング用にローカル再計算のまま、**保存/ログ用の値だけが Phoenix 提供値に置き換わる**。
- 保存された `slate_context` は `phoenix_request_cache_side_effect.rs:92-98`（`LogSlateContext` 有効時）でキャッシュされ、`models/candidate.rs:190-204` 経由で学習ログ (`ScoreInfo`) に載る。

**Xユーザー/クリエイターへの影響:**

- **既定オフのため現時点の体感変化なし**。
- 有効化された場合、「同じ著者の投稿を1画面に何本まで許すか」の判定に使う **`k` の出どころ**が home-mixer 内部の重み付きスコア順から Phoenix（モデルサーバ）側のスレート計算に変わる。両者の順序が食い違う分だけ、**連投抑制の掛かり方が投稿単位でわずかにずれる**（強くも弱くもなりうる／要確認: Phoenix 側の計算定義は本リポジトリに含まれず、`candidate_slate_context` の実装は非公開）。
- 副次的に重要なのは**学習ログの一貫性**: これまで「モデルが見たスレート状態」と「home-mixer が記録したスレート状態」がずれ得たが、Phoenix 提供値に統一することで **学習時と配信時の特徴量が揃う**方向。中長期的にはランキング精度の底上げ要因（＝多様性・話題重複ペナルティの効きが安定する方向）。

**影響度:** 小（現時点。既定オフ）／有効化時は中
**影響ユーザー層:** 同一著者の連投を多く見る層、同一話題（セマンティックID）が集中しがちなタイムラインの閲覧者。
