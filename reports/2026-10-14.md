## 非IT精通者向け：運用方法のまとめ（行動指針）

今回は **「本日から既定で効く変更」が4件**（うち1件はランキング重みの数値変更）あり、9月以降で最も実影響の大きい更新のひとつです。

### いますぐ効いてくること

- **「いいね」の重みが 0.5 → 0.66 に上がりました（+32%）。**
  重みは「あなたがその投稿にいいねする確率の予測値」にかかる倍率です（生のいいね数にかかるのではありません）。つまり **「見た人がいいねしそうな投稿」の順位が今日から相対的に上がりました**。
  → **行動指針：** いいねを押させる投稿（共感・納得・保存したくなる内容）の価値が上がりました。ただし依然として 返信5.0・引用5.0・DM共有5.0・リンクコピー20.0 の方が桁違いに重いので、「いいね狙い」に全振りする話ではありません。あくまで最下層の指標が少し効くようになった、という程度です。

- **「動画を開く」の重みが 0.07 → 0.02 に下がりました（-71%)。**
  **動画投稿がFor Youで有利になる度合いが本文フィード上では大きく縮みました**。
  → **行動指針：** 「とりあえず動画にしておけば伸びる」はさらに弱まりました。動画は「開かれること」より **滞在時間・返信・共有** で評価される方向です。なお縦型動画カルーセル（別枠）は `video_open_score` で選抜されるため、カルーセル経路への影響はありません（カルーセル自体は依然 既定オフ）。

- **「読まれた秒数（連続滞在時間）」の重みが 0.004 → 0.006 に上がりました（+50%）。**
  → **行動指針：** **じっくり読ませる投稿（長文・読み物・情報量のある画像）が有利**になりました。10月8日の「滞在時間の予測方式の精緻化(CREAD)」と合わせて、「数字は伸びないが読まれている投稿」が評価される流れが続いています。

- **「興味がない」を押される予測のペナルティが -47.52 → -52.272 に強化されました（-10%）。**
  → **行動指針：** 「クリックはされるが見た人をうんざりさせる」タイプの投稿（煽り・釣り・連投）の不利がさらに強まりました。

### 3. 記事（Article）の本文メディア・カバー画像をNSFWゲーティングに算入【影響度：中〜大】

**メカニズム**

- 「投稿にメディアがあるか」の述語が、投稿本体のメディアだけでなく **記事の本文メディア・カバー画像のいずれか** を見るようになりました：
  `tweet_has_media = TweetHasMedia reads (Tweet, ArticleMediaEntities, ArticleCoverMedia) => |_, (tweet, body, cover)| tweet.has_media() || body || cover`
  （`visibility-filtering/rules/rule_spec/predicates.rs:194-195`）
  旧実装は `HasMedia reads Tweet => |_, tweet| tweet.has_media()`（投稿本体のみ）でした（旧 `visibility-filtering/rules/rule_spec.rs:789`）。
- 取得経路が新設：Strato の `article/fields/mediaEntities.ArticleEntity` と `article/fields/coverMedia.ArticleEntity` を閲覧者コンテキスト付きで取得（`visibility-filtering/clients/article_client.rs:12-14, 44-96`）。権限エラーは「不明」として扱い、障害時に過剰ブロックしない設計です（同 109-128）。
- この述語を使っているのは **センシティブ系ルール群** です（`visibility-filtering/rules/tweet_rules.rs:245-340, 728-840`）：
  - `SENSITIVE_VIEWER_LOGGED_OUT_DROP_*`：ログアウト閲覧者には**投稿自体をドロップ**
  - `SENSITIVE_VIEWER_UNDERAGE_DROP_*`：18歳未満にはドロップ
  - `SENSITIVE_VIEWER_NO_STATED_AGE_DROP_*`：年齢未申告（対象国のみ）にはドロップ
  - `NSFW_*_BLUR_*`：センシティブ表示をオフにしている閲覧者にはぼかし／警告
- ゴールデンコーパスに意図が明示されています（`visibility-filtering/rules/golden_corpus/article.rs:70-130`）：成人向けフラグ付き著者の記事は「カバー画像あり」または「本文メディアあり」で `restricts = true`（TimelineHome・TimelineHomeRecommendations・ImmersiveExpandedRecommendations でも制限）、**メディアなしの記事は `restricts = false`**（従来どおり TimelineHomeHydration のみ）。

**影響**

- **記事（長文投稿）を書くクリエイター：** 成人向けフラグが付いたアカウント、またはNSFWメディアラベルが付いた記事は、**画像を1枚付けるかカバー画像を設定するだけで、ログアウト閲覧者・未成年・年齢未申告の閲覧者に完全に届かなくなります**。テキストのみの記事であれば従来どおりです。
- **一般閲覧者：** これまで記事経由で素通りしていたセンシティブメディアが、通常の投稿と同じ基準でゲートされます（安全側の変更）。
- 影響を受ける層：センシティブ領域（成人向け・暴力・医療など）で記事機能を使うクリエイター、ログアウト閲覧者、年齢未申告ユーザー。

### 4. 会話ルート著者のブロック判定を3経路に拡張【影響度：中】

**メカニズム**

- 旧：`ViewerIsBlockedByConversationRootAuthor reads BlockedByReplyRoot => |_, blocked| blocked`（返信先投稿の著者のみ、旧 `visibility-filtering/rules/rule_spec.rs:897`）。
- 新：3つの経路の論理和（`visibility-filtering/rules/rule_spec/predicates.rs:317-321`）
  ```
  reads (BlockedByReplyRoot, BlockedByConversationRoot, BlockedByConversationRootPost)
  => |facts, (direct, from_control, fetched)| direct || fetched || (from_control && facts.is_reply())
  ```
- 新しい取得ノードが2つ追加（`visibility-filtering/hydration/plan.rs:299-316`）：会話コントロール設定から判明したブロック著者（`ConversationControlBlockAuthor`）と、**会話ルート投稿を実際に取得してその著者のブロック関係を確認する経路**（`ConversationRootPost` → `BlockedByConversationRootPost`）。
- このとき発動するルール（`visibility-filtering/rules/tweet_rules.rs:1010-1015`）：
  ```
  BLOCKED_VIEWER_LIMITED_ENGAGEMENT_ROOT_AUTHOR_BLOCKED_VIEWER
    when: viewer_is_blocked_by_conversation_root_author()
    audience: Everyone
    action: limit(LimitedEngagementReason::RootAuthorBlockedViewer)
  ```
- 会話コントロール（コミュニティ限定など）と重なった場合は理由が2つ併記されます（`visibility-filtering/rules/golden_corpus/relationship.rs` の `nested_root_author_block_community_conversation` 行）。

**影響**

- **ブロックされた側：** スレッドの元投稿者にブロックされていると、**そのスレッドの深い階層の返信に対しても操作が制限されます**。これまでは「直接の返信先の著者」が判定対象だったため、孫返信・ひ孫返信にぶら下がる形でスレッドに参加できる余地がありました。
- **ブロックした側（スレッド主）：** ブロックの効き目が会話全体に及ぶようになり、「ブロックしたのに自分のスレッドに居座られる」状況が減ります。
- 制限される操作の内訳（返信のみか、リポスト等も含むか）は設定（`LimitedActionsPolicies`）側で決まるためコードからは確定できません **(要確認)**。

## 不確実な点（要確認）

1. **重み変更の実効果の大きさ**：重みは予測確率への倍率であり、各ヘッドの予測値の分布（スケール）がコードに含まれないため、「いいね +32%」が最終順位をどれだけ動かすかは定量できません。いいねは絶対値が小さい重み（0.66 対 返信5.0）なので、順位の激変ではなく「同程度のスコアの投稿間での並び替え」に効く範囲と見るべきです。
2. **`RootAuthorBlockedViewer` で制限される操作の内訳**：返信のみか、リポスト・引用も含むかは `LimitedActionsPolicies`（設定側）で決まり、コードからは確定できません。
3. **ZeroFav retrieval の本番有効化状況**：home-mixer 側にオン/オフのパラメータがなく、retrieval サービス側のデータセット設定に依存するため、実際に候補が供給されているかは判断できません（計測コードが入ったこと自体は、何らかのトラフィックがある示唆です）。
4. **AESの実際の執行割り当て**：どの分類器にどのアクション・どの信頼度バンドが割り当てられているかは Manhattan のレコードと GrowthBook 設定にあり、リポジトリには含まれません。ルールYAMLのしきい値（フォロワー数 12.34 / 12345.67、PageRank 50.0）はコード内に「本番とは異なるモック値」と明記されています。
5. **ページRLの本番投入時期**：学習設定（`immersive_page_rl`）は存在しますが、home-mixer 側に対応する配線・パラメータはありません。イマーシブ面（全画面動画）が最初の適用先と推測されますが、確定情報ではありません。
6. **記事メディア取得の失敗時挙動**：Strato の権限エラーは「不明」扱いで素通りする実装ですが、取得障害が多発した場合に記事のゲーティングがどの程度抜けるかは運用依存です。
7. **`CLIENT_CARD_CLICK`（アクション番号44）の廃止**：同じ番号が `SERVER_TWEET_REACT_WITH_VIDEO` に差し替えられており、カードクリックの学習ラベルが廃止されたのか別番号に移ったのかはコードから判断できません。
