今回は「**広告の出方**」に手が入った日です。見た目の派手さはありませんが、1件は**今日から効く既定値の差し戻し**で、残りは**広告をもっと詰める方向の新方式**の仕込みです。あわせて縦型動画が「開かれるか」から「**どれだけ長く見られるか**」を軸に評価される準備が、学習側と配信側の両方で進みました。

### いますぐ知っておくべきこと

- **【今日から効く・広告】広告の「隣に置いてよい投稿」の判定が、新しい方式（v2）から古い方式（v1）に差し戻されました。**
  広告は、隣接する投稿のブランドセーフティ判定（Safe / LowRisk / MediumRisk / HighRisk）を見て置き場所を決めます。この判定を Grok の新ラベル（`GROK_SFA_V2` / `GROK_NSFA_LIMITED_V2` / `GROK_NSFA_V2` / `GROK_NSFA_EXPANDED_V2`）で行う v2 方式が、**10月3日から既定ONだったものが今回 OFF に戻されました**（`home-mixer/params/param.rs:938-943`、`rust_home_mixer_ads_bs_v2_exp_enabled` が `true` → `false`）。判定の切り替え地点は `home-mixer/candidate_hydrators/ads_brand_safety_vf_hydrator.rs:110-119` です。
  **メカニズム上の違いは次の2点です。** (1) v1（`home-mixer/models/brand_safety.rs:103-131`）は「Grokに採点されたか」を**旧ラベル `GROK_SFA` / `GROK_NSFA_LIMITED` の有無だけで**判定し、無ければ `MediumRisk` にします（同:116-120）。v2（同:158-188）は**新ラベルで**同じ判定をします（同:173-177）。つまり**新ラベルだけが付いている投稿は、v1 では「未採点」＝ `MediumRisk` に落ちます**。(2) v1 の中リスク一覧には `NSFA_HIGH_PRECISION` と `GROK_NSFA` が、低リスク一覧には `NSFA_LIMITED_INVENTORY` と `GROK_NSFA_LIMITED` が含まれますが（同:82-101）、v2 の一覧（同:133-156）からはこれらが外れ、代わりに v2 系ラベルが入ります。
  `MediumRisk` の投稿は、**ブランドセーフティ要件が最も緩い広告（BSR_HIGH）の隣にしか置けず、しかも枠数が半分に制限されます**（`home-mixer/ads/multi_risk_blender.rs:70-78`、`home-mixer/ads/neighbours.rs:261-266` の `safe_slot_estimate`）。
  → **行動指針：** **一般ユーザーとして：** 広告の**本数が減る、または広告の種類が偏る**可能性があります（安全な隣接枠が足りないと広告が落とされる設計のため）。広告が減って見えても、設定変更や不具合ではありません。**クリエイターとして：** 自分の投稿が「広告の隣に置ける投稿」とみなされるかの基準が変わりました。**新ラベルだけが付いている投稿は中リスク扱いに戻るため、広告隣接の対象から外れやすくなります。** ただしこれは**収益分配の可否そのものではなく、広告の配置可能性**の話です（本リポジトリには収益分配ロジックは含まれません／**要確認**）。本番で実際にどちらのラベル体系が主に付与されているかはリポジトリから判定できないため、影響の大きさは**要確認**です。

- **【要監視・まだ既定OFF】広告をより多く詰め込む新方式が2本入りました。テストで「現行方式以上の広告本数」が保証されています。**
  現行の既定は `multi_risk` 方式です（`home-mixer/params/param.rs:931-936`、`rust_home_mixer_ads_blender` の既定値 `"multi_risk"`、今回変更なし）。そこへ選択肢として2本が配線されました（`home-mixer/selectors/blender_selector.rs:65-66`）。
  1. **`slot_spread`（枠分散方式、`home-mixer/ads/slot_spread_blender.rs` 新規272行）：** ページに入る広告枠数を先に決め、**その枠をページ全体に等間隔でばらまきます**（同:104-115 の `spread_slots`：余りの投稿数を枠数で割って均等配分）。さらに「センシティブな広告（BSR_LOW）には安全な投稿を2枚確保する」「後続にセンシティブ広告が控えているときは、先の広告に低リスク投稿を優先的に充てて安全枠を温存する」という先読みが入っています（同:153-157, 204-206 の `prefer_low`）。
  2. **`least_movement`（最小移動方式、`home-mixer/ads/least_movement_blender.rs` 新規485行）：** **オーガニック投稿がスコア順の本来の位置からどれだけズレるかの合計（`movement`）を最小化**しながら、ブランドセーフティの隣接制約を満たす配置を探します（同:453-461）。注目すべきは重み設定で、**最初の広告はできるだけ上部（本来の最早位置）に固定しようとする力が、2本目以降の25倍強く効きます**（同:13-14：`SLACK_WEIGHT = 2` に対し `FIRST_AD_SLACK_WEIGHT = 50`、同:446 のコスト式 `cost + weight * slack`）。つまり「**1本目の広告はページ上部に、その代わりオーガニックの並びは動かさない**」という設計です。
  **そして両方式には「現行方式より広告を減らさない」ことがテストで固定されています**（`home-mixer/ads/tests/blender_comparison_test.rs:722-765`：`total >= baseline_total`、`multi_risk` の配信本数が下限）。同時に、ブランドセーフティ違反（センシティブ広告が低リスク投稿の隣／除外ハンドル・除外キーワードの隣／中リスク投稿の隣）は**ゼロであることも両方式に対して検証されています**（同:690-712）。
  あわせて「**なぜ広告が入らなかったか**」を記録する計測が共通化されました（`home-mixer/ads/health_metrics.rs` 新規131行）。制約要因を **ads_supply（広告在庫不足）／ spacing（間隔制約）／ safe_posts（安全な隣接投稿の不足）** に切り分けて数えます（同:89-101）。
  → **行動指針：** **現時点で運用を変える必要はありません**（既定は従来方式のまま）。ただし、上の「v2差し戻し」「制約要因の計測整備」「現行以上の本数を保証する新方式2本」は、**1つの文脈として読めます**：広告の充填が「安全な隣接投稿の不足」で詰まっており、**同じ安全基準のまま広告本数を増やす**方向の作業が進んでいます。有効化された場合に起きることは、**一般ユーザーには広告密度の上昇（とくに `least_movement` ではページ最上部に近い位置への1本目の挿入）**、**クリエイターには「広告の隣」に置かれる投稿が増えること**です。`least_movement` が選ばれた場合、オーガニックの並び順そのものへの影響は現行方式より**小さく**なります（並びのズレを最小化する設計のため）。

- **【要監視・既定の重みは0】縦型動画（動画カルーセル）の評価軸に「期待視聴秒数」が追加されました。**
  カルーセルに出す動画の並び順は、これまで「**開封スコア**」と「**没入画面での高品質視聴（VQV）スコア**」の重み付き和でした。今回ここに第3項として **「開封スコア × 没入画面での滞在時間」** が加わりました（`home-mixer/util/video_carousel.rs:178-189`）。これは実質 **「開かれる確率 × 開かれたら何秒見られるか」＝ 期待視聴秒数** です。新パラメータは `rust_home_mixer_video_carousel_open_times_immersive_dwell_weight`（`home-mixer/params/param.rs:1257-1262`、**既定 0.0 ＝ 無効**）。カルーセル全体の既定も OFF（同:1190-1196 の `EnableVideoCarousel = false`）です。この重みが 0 以外になると、没入スコアに基づく並べ替え経路が有効化されます（`home-mixer/util/video_carousel.rs:18-24`）。
  **学習側も同じ方向に動きました。** 縦型動画のページRL学習設定に `immersive_page_rl_cread` という新バリアントが追加され（`phoenix/xrex/configs/xrecsys.py:421-431, 506-512`）、滞在時間の学習目的が **Tweedie損失＋MAE（重み0.1/0.1）から CREAD（同0.1/0.1）へ入れ替わりました**。CREAD は滞在時間を**対数間隔のしきい値群に分解し「各しきい値を超えたか」を多数の二値分類として学習した上で秒数を復元する**方式です（`phoenix/xrex/models/loss_recsys.py:110-170`）。これは**本流のランキング設定 `home_direct_packed` が既に採用している方式**（同 `configs/xrecsys.py:278-282`）で、**縦型動画のページRLモデルを本流と同じ滞在時間目的に揃えた**ことになります。
  → **行動指針：** **動画クリエイターとして：** 評価軸が「**サムネで開かせる**」から「**開かせた上で長く見せる**」へ移る準備が、配信側・学習側の両方で整いました。有効化時に不利になるのは **「釣りサムネで開封率は高いが、開いた直後に離脱される動画」** です。有利になるのは **冒頭で引き込み、最後まで見られる構成**です。なお既定重みは 0 のため**今日の時点では挙動は変わっていません**。本番の実値は**要確認**です。

- **【小さいが体感しうる・既定ON】カルーセルで見た動画が、通常フィードに再び出てくるようになりました。**
  X は「直近10分に出した投稿（最大100件）」を記録し、同じ投稿の再表示を抑えています（`home-mixer/params/param.rs:1128-1139`：`ExcludeServedTweetIdsDuration = 10`分、`ExcludeServedTweetIdsNumber = 100`件）。今回、この**重複排除リストを作るときに「動画カルーセル枠」として出した分を除外する**ようになりました（`home-mixer/query_hydrators/served_history_query_hydrator.rs:99`：`entry.entity_type != EntityIdType::VIDEO_CAROUSEL_MODULE`）。
  効果は2つあり、向きが逆です。(1) **カルーセルに出た動画は「まだ出していない」扱いになり、直後の通常フィードやカルーセルに再登場しうる。** (2) 一方で**100件の枠がカルーセル動画に食われなくなるため、通常フィードの投稿の重複排除はむしろ効きやすくなる**（`.take(100)` が除外後に適用される設計のため、同:85-109）。なお「カルーセル枠そのものを再表示しない」疲労制御（既定60分、同:1197-1202）は別経路なので従来どおりです。
  → **行動指針：** **一般ユーザーとして：** カルーセルで見た（あるいは見送った）動画が通常フィードに再び現れることがあります。「さっき見たはず」という感覚は正しく、不具合ではありません。繰り返し出したくない動画は「興味がない」で明示的に外すのが有効です（カルーセル経由の視聴は重複排除の根拠として使われなくなったため）。カルーセル自体は既定OFFなので、カルーセルを見ていない環境では影響しません。

- **【小・実質ON】削除済み・存在しない投稿の返し方が、「失敗」から「見つかりません」に変わりました。**
  可視性フィルタ（VF）が投稿または著者を見つけられなかったとき、`evaluate_tweets` 系の応答がこれまで**「失敗（Failed）」**だったものが、**明示的な「見つかりません（NotFound）」**を返すようになりました（`visibility-filtering/treatment.rs:772-782`）。引用元の著者が存在しない引用投稿でも同様です（`visibility-filtering/quote.rs:779-800` のテスト名が `a_not_found_quoted_author_still_fails_the_served_inner` → `..._sends_not_found_for_the_served_inner` に変更）。クライアント側も `NotFound` の受理を前提に書き換えられました（`visibility-filtering-client/evaluated.rs:68-73`：従来は `bail!("VF sends only found or filtered")` でエラー扱い）。
  → **行動指針：** **一般ユーザーとして：** 削除されたアカウントの投稿を引用している投稿などで、**「この投稿は利用できません」が安定して表示されるようになります**（従来は通信エラー的な扱いで、表示が不安定になりえた経路）。見え方が良くなる方向の変更で、こちら側の操作は不要です。

## 変更サマリ

1. **広告ブランドセーフティ判定 v2 が既定ON→OFFに差し戻し**（10月3日からONだったものを撤回）。新Grokラベルのみが付いた投稿は「未採点」＝中リスク扱いに戻り、広告の安全な隣接枠の供給が減る方向。
2. **広告挿入の新方式2本（`slot_spread` / `least_movement`）を新設**。既定は従来の `multi_risk` のままだが、**テストで「現行方式以上の広告本数」が下限として固定**されており、ブランドセーフティ違反はゼロを維持。`least_movement` はオーガニックの並びのズレを最小化しつつ、1本目の広告をページ上部に強く引き寄せる設計（重み50対2）。
3. **縦型動画の評価軸に「開封率×没入滞在時間＝期待視聴秒数」を追加**（既定重み0.0）。学習側では縦型動画ページRLの滞在時間目的を Tweedie/MAE から CREAD（本流ランキングと同方式）へ差し替えた新設定を追加。
4. **ページ単位並べ替えの実用化が前進**：実際に出した並びの記録（ページログ）が既定ON、ページRLとシーケンスパッキング／候補専用レイヤーの非互換が解消。ただし**並び順を変えるスイッチ自体は依然OFF**。
5. **広告にリードジェン・コンバージョンの予測ヘッドを新設**（即時ストリーム＋クリック条件で学習）。
6. **VFは約50ファイルの大規模リファクタでルール内容は不変**。実挙動の変更は「見つからない投稿・著者を『失敗』ではなく『見つかりません』として返す」1件のみ。
