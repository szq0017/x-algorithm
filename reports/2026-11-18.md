## 非IT精通者向け：今日の差分を踏まえた運用方法のまとめ

今日の最重要点は、**本番の既定値そのものが1つ書き換わった**ことです。実験用のスイッチ追加ではなく、全ユーザーに効く数値の変更です。

- **「リンクをコピー」で共有される投稿が、今日から最強クラスの評価対象になりました。**
  投稿の「リンクをコピー」ボタンで共有される確率の重みが **0.0 → 20.0** に変わりました（`home-mixer/params/param.rs:496`）。これまでこの行動は**ランキングに一切寄与していませんでした**（重み0＝無視）。今日からは、いいね（0.5）の40倍、リポスト（1.0）の20倍、DM共有（5.0）の4倍という最大級の重みが付きます。相互フォロー相手への返信（5.0＋ボーナス15.0＝20.0）と並ぶ最上位です。
  → **「URLをコピーして他所（LINE・Slack・Discord・ブログ・他SNS）に貼りたくなる投稿」が構造的に最も伸びます。** 具体的には、保存・共有したくなる実用情報、まとめ、引用したくなる一次情報、他人に見せて説明したくなる図表などです。
  → 逆に「X内でのいいね稼ぎ」の相対価値は下がりました。**X外に持ち出される投稿**が、今日から明確に優遇されます。
  → なお効くのは**予測確率**です。「自分でURLをコピーして回る」自演は効きません（コピーされる確率を予測するモデルが、投稿の性質から推定します）。

- **「滞在時間」と「エンゲージメント」を別々の倍率で扱う仕組みが入りました（既定OFF）。**
  これまでフォロー外（OON）投稿の抑制は、スコア全体に0.75を掛ける**一律の値引き**でした。今日入った仕組みでは、**「滞在時間で稼いだ分」と「いいね等で稼いだ分」に別々の倍率**をかけられます（`xai-value-model/scoring.rs:338`）。フォロー内・フォロー外それぞれに2つずつ、計4つの倍率が新設されました。
  → つまり運営は「**フォロー外の投稿は、長く見られた分だけは評価するが、いいね系は値引きする**」（あるいはその逆）という細かい調整ができるようになりました。テストコードには「フォロー外はエンゲージ0.6倍・滞在0.9倍、フォロー内はエンゲージ1.2倍・滞在0.7倍」という例が書かれています（`vm-ranker/scoring/mod.rs:249` 付近。ただし**これはテスト用の架空設定で、本番配分ではありません — 要確認**）。
  → 当面の行動指針は変わりませんが、「**滞在だけ**」「**いいねだけ**」の片寄った投稿は、どちらの方向に調整されても取りこぼすリスクがあります。両方が自然に起きる投稿が最も安全です。

- **広告の本数が「そのページの出来の良さ」で変わるようになりました（既定OFF）。**
  昨日までの広告間引きは「ユーザーの使い込み度合い（8段階）」別でした。今日はこれに加えて、**そのとき表示しようとしている投稿の上位20件の平均スコアを見て、ページを「低・中・高」の3段階に分類し、段階ごとに広告の本数と間隔を変える**仕組みが入りました（`home-mixer/ads/user_load.rs:152`）。
  → おすすめの中身が良い（＝スコアが高い）タイミングでは広告を増やし、中身が薄いタイミングでは減らす、といった運用が可能になります（配分値は公開コードに無いため **要確認**）。広告は最低50％は残る設計です。

- **フォロー外投稿の「多様性（同じような投稿を連続させない）」判定が、画面の種類を区別するようになりました。**
  「直前に見た投稿」の履歴に、それが**初回表示・引っ張って更新（ポーリング）・下にスクロールして追加読み込み**のどれで出たものかという情報が付きました（`home-mixer/scorers/vm_ranker_request.rs:169`）。
  → 現時点では情報を渡しているだけで挙動は変わりません。将来的に「更新直後は似た投稿を許すが、スクロール中は散らす」といった画面別の調整につながります。

- **有料プラン（Premium / Premium+）が、実験の振り分け条件として使えるようになりました。**
  これまで実験の対象絞り込みは国・言語・アプリ・アカウント年齢などで行われていましたが、今日**契約プランそのものを条件に書ける**ようになりました（`home-mixer/models/fs_recipient.rs:50`）。
  → 「Premium+ ユーザーだけランキングを変える」という運用が技術的に可能になりました。無料ユーザーと有料ユーザーでおすすめの挙動が将来的に分岐しうる、という前提で見てください。

- **動画の評価に使う「どのくらい見続けたか」の予測が、3種類増えます。**
  これまで1種類だった連続値予測（滞在秒数）に、**没入表示（フルスクリーン）での滞在、動画の続き見、プロフィール閲覧秒数**の3つが追加される準備が入りました（`phoenix/xrex/models/recsys_model.py:325`）。
  → 「**投稿を見た後にプロフィールまで見に来る**」という行動が、独立した評価軸として学習対象になりつつあります。プロフィールの作り込み（固定ポスト・自己紹介）が、間接的にランキングへ効く余地が広がります。

## 変更点ごとの詳細

### 1. 「リンクをコピー」共有の重み: 0.0 → 20.0 【本番既定値の変更】

**メカニズム**

`home-mixer/params/param.rs:496` の既定値が `0.0` から `20.0` に変わりました。このファイル冒頭には `// mirrored from config feature-switch defaults; last sync 2026-11-17T16:00:33Z` と書かれており、**本番の設定既定値のミラー**です（実験用の新規スイッチではありません）。

この重みは `xai-value-model/scoring.rs:99` で `share_via_copy_link_score`（＝そのユーザーがその投稿のリンクをコピーする予測確率）に掛けられ、他の全ヘッドと合算されてスコアになります。`xai-value-model/weights.rs:57` のとおり、正のヘッドの合計に含まれます。

現在の主要な重みとの比較:

| 行動 | 重み |
|---|---|
| **リンクをコピーして共有** | **20.0（←0.0）** |
| 相互フォロー相手への返信 | 5.0 + 15.0 = 20.0 |
| 返信 | 5.0 |
| 引用 | 5.0 |
| DMで共有 | 5.0 |
| 著者をフォロー | 4.0 |
| 共有（一般） | 2.0 |
| リポスト | 1.0 |
| いいね | 0.5 |
| クリック | 0.4 |
| 滞在（離脱せず読んだ） | 0.05 |
| 滞在秒数（1秒あたり） | 0.004 |
| 報告 | -234.0 |

**Xユーザー/クリエイターへの影響**

- 「X外に持ち出して引用・共有される投稿」が、単発のいいね・リポストより圧倒的に重く評価されます。実用情報、保存価値のあるまとめ、他人に転送して説明したくなる図表・データ、ニュースの一次情報などが有利です。
- 逆に、X内での反応は多いがX外にリンクが出ていかない投稿（内輪ネタ、リプライ合戦、感情的な短文）は、相対的に地位が下がります。
- ゼロからの変更なので、**昨日までの学習・配信実績にこの軸は反映されていません**。切り替え直後はおすすめの中身が体感レベルで変わる可能性があります。
- 重みが掛かるのは**予測確率**であり、実際のコピー回数ではありません。コード冒頭のコメント（`home-mixer/params/param.rs:280` 付近）が明示するとおり、自分でURLをコピーして回る行為や、グループチャットで直接URLを配る行為はランキングに寄与しません（ホームタイムラインで配信された投稿上の行動のみ計上）。

### 2. エンゲージメント項と滞在時間項を別倍率に分離（既定OFF）

**メカニズム**

- 新しい型 `ClassFactors { engagement, dwell_time }` が追加されました（`xai-value-model/inputs.rs:26`）。クエリ単位の文脈 `QueryScoringContext` に `oon_factors` と `in_network_factors` の2枠が追加されています（同:44）。
- 新パラメータ4件（`vm-ranker/params.rs:248`〜`266`）: `oon_engagement_weight_factor`、`oon_dwell_time_weight_factor`、`in_network_engagement_weight_factor`、`in_network_dwell_time_weight_factor`。**既定値はすべて `-1.0`**。負値は「未設定」扱いで、`ClassFactors::new` が `None` を返して無効化されます（`xai-value-model/inputs.rs:32`）。片方だけ設定した場合、残りは従来の一律係数（OONは0.75、フォロー内は1.0）にフォールバックします（`vm-ranker/scoring/value_model.rs:130`）。
- 計算の中身（`xai-value-model/scoring.rs:338-364`）: 候補のスコアから「滞在秒数ヘッドの寄与分」（`dwell_time × cont_dwell_time`、0〜スコア上限でクランプ）を切り出し、
  `level × (engagement係数 × (スコア − 滞在分) + dwell_time係数 × 滞在分)`
  を最終スコアとします。`level` はフォロー内投稿のうちOON再採点対象（フォロー内の返信・リポスト）にのみ0.75が掛かる従来挙動を引き継ぎます。
- 適用範囲の制限: 乗算モード（`multiplicative`）およびオフセット前乗算モード（`multiplier_pre_offset`）では**この機構は無効**（同:339、`vm-ranker/scoring/value_model.rs:198` の計測も同条件）。昨日のレポートで扱った「掛け算方式」とは**併用されない**排他の関係です。
- トピック要求（話題タイムライン）および新規ユーザーの場合は、従来どおり一律係数のみで、クラス別倍率は適用されません（`vm-ranker/scoring/value_model.rs:139-162`）。

**Xユーザー/クリエイターへの影響**

- 既定OFFのため**現時点の挙動は変わりません**。
- 有効化された場合、「フォロー外からの流入」の性質が変わります。たとえばOONのエンゲージ係数を下げ滞在係数を上げれば、**フォロー外の投稿は「じっくり読まれる長文・長尺」が通りやすく、「いいねを集める瞬発型」が通りにくく**なります。逆向きの設定も可能です。
- フォロー内に1.0超の係数（テスト例では1.2）を置くことも可能な設計で、**フォロー中の投稿を従来より強く押し上げる**方向の調整もできます。
- 具体的な本番配分は公開コードに含まれません（**要確認**）。

## 不確実な点（要確認）

- **「リンクをコピー」重み20.0の実際の効果量**は、`share_via_copy_link_score`（予測確率）の典型的な大きさに依存します。他ヘッドと比べて確率の絶対値が小さい行動であれば、重み20.0でも寄与は中程度にとどまります。公開コードから確率分布は読めません。
- **クラス別倍率の本番配分値**は公開コードに含まれません。`vm-ranker/scoring/mod.rs:249` 付近にある「FR: OON 0.6/0.9、フォロー内 1.2/0.7」「JP: OON滞在のみ 0.9」はテストフィクスチャであり、本番の実験設定ではありません。
- **広告ページティアの閾値・残存率**（`low`/`high` と各ティアの keep_pct / spacing）は公開コードに既定値（0.0・空配列）しかなく、実運用値は不明です。
- **新しい連続値予測ヘッド3種が本番で既に使われているか**は、学習設定が公開範囲外のため不明です。コード上は受け口の整備のみ確認できます。
- **teacher サイドエフェクトのサンプリング率と対象アクション**は既定0／空であり、実運用で有効化されているかは不明です。
- DPP の `request_type` を実際に使う採点ロジックは、公開されている `dpp_model.rs` には見当たりません。vm-ranker proto（`xai-vm-ranker-proto`）の定義自体は公開範囲外のため、フィールド追加の全容は確認できません。
