- **今日の本命は「返信（リプライ）の採点」の作り**。2つの変更が入り、**どちらも返信で伸ばしたい人に直接効く**。
  - **① 返信の点数は「一度下がったら二度と上がらない」仕組みになった。** 返信はAIが採点して返信欄の並びが決まるが、今回**「新しい点数が、保存済みの点数より高いときは書き込まない」**という条件が入った。つまり**点数は同じか下がるだけで、上がることはない**。
    - **実務上の意味**: **投稿直後の第一印象がすべて**。返信を投げた瞬間の文面・文脈でAIに低く採点されると、あとで会話が盛り上がっても、返信を編集しても、**その返信の評価は戻らない**。

## 変更点ごとの解析

### 1. 【本命・稼働中】返信ランキングスコアが「下がる一方」の単調ラチェットになった

**メカニズム (コード根拠):**

- `grox/flows/reply_spam/strato_loader.py:29-31` — 既存スコアの読み出し API を新設。
  ```python
  @classmethod
  async def fetch_reply_ranking_score(cls, post_id: str) -> ReplyRankingScore | None:
      return await cls.strato.fetch(int(post_id))
  ```
- `grox/flows/reply_spam/task_write.py:116-136` — 書き込み直前に既存スコアを読み、**新スコアが既存より高ければ書き込まずに `return`**。
  ```python
  if (existing is not None and existing.score is not None and score > existing.score):
      Metrics.counter(...).add(1, attributes={"reason": "higher_than_existing"})
      return
  ```
- 結果として、ある投稿IDに対して保存される `score` は **単調非増加**（初回書き込み値が上限）になる。
- 読み出し失敗時（例外）は `existing = None` のまま**書き込みを続行**する (`task_write.py:120-124`) ＝ Strato 障害時はフェイルオープン（従来どおり上書き）。
- 波及先も同じ `return` の後段にあるため、**すべての下流に伝播する**:
  - `task_write.py:139` — `score == 0.0` のときの `_apply_reply_spam_label`（スパムラベル付与）。0.0 より小さい既存値は事実上存在しないので、**スパム判定の書き込みは常に通る**。
  - `strato_loader.py:33-44` — 主ストア `strato.put` に加え、**スコア ≤ 1.0（低品質）のときだけ** atla/pdxa の地域キャッシュへ二重書き込み（8/25 レポートで確認済みの経路）。ラチェットにより、**一度キャッシュに入った低スコアは、以後の再採点では消えない**。
  - `task_write.py:146-152` — Kafka v2 ストリームへの publish も同様にスキップされる＝**学習・分析側のログにも改善後のスコアが流れない**。

**Xユーザー/クリエイターへの影響:**

- **返信は「投げた瞬間の一発勝負」になった。** 返信が最初に採点された時点の点数が、その返信の**生涯の上限**になる。後から会話の文脈が整っても、返信本文を編集しても、**返信欄での序列は戻らない**。
- **不利になる使い方**: 「まず短く反応して後から補足」「連投スレッドの1本目が単体では意味を成さない」「元投稿の全文が読み込まれる前に採点された」——いずれも**低い初回スコアが確定して固定される**リスクがある。
- **有利になる面**: 逆方向の保護は無いが、**"下げ"の再採点は従来どおり通る**ため、この変更は純粋に**「上げ」の経路だけを塞いだ**もの。運営意図としては、8/25 の「低スコアのみ地域キャッシュへ二重書き込み」と同じく、**悪い返信を確実に沈め続ける**ための投資と読める。
- **誤判定のリスク**: AI採点は完璧ではない。**一度の誤った低評価が、その返信について事実上恒久化する**。地域キャッシュ側に TTL（保持期限）があるかどうかはこのリポジトリからは読めない（要確認）ため、「時間が経てばリセットされる」とは断定できない。
- **返信でリーチを取る戦略への含意**: **返信は下書きしてから投げる**。「返信欄の上位に出るかどうか」を狙うなら、初回採点で通る品質——文脈が独立して読める・関連性が明確・宣伝色や定型文でない——を**最初の一投で**満たす必要がある。

**影響度:** **大**（返信を使う全ユーザーに恒常的に効く。ただし体感は緩やかに現れる）
**影響ユーザー層:** 返信で露出を取るアカウント全般。特に**大アカウントの投稿にぶら下がって伸ばす層**と、**会話型で少しずつ書き足すユーザー**。

**Xユーザー/クリエイターへの影響:**

- **平常時の影響はゼロ。** キャッシュは障害時の保険であり、正常時の判定は変わらない。
- **メディア基盤(TES)の障害・タイムアウト時**に、**センシティブなメディアが年齢確認・閲覧注意なしで表示されうる**（フェイルオープン）構図に戻った。地域規制のかかったメディアも同様に素通りしうる。

- 一般ユーザーが今日から取るべき行動は無い。**障害時のフィードでセンシティブ表示が緩む可能性がある**、という知識にとどめてよい。

**影響度:** **小**（平常時は無影響。障害時のみ・かつ移行中の実装）
**影響ユーザー層:** 全ユーザー（障害時のみ）。特に年齢制限・地域制限の対象コンテンツ。
