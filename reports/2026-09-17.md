## 非IT精通者向け・運用方法のまとめ（行動指針）

- **今日、実際に「今すぐ For You の並びが変わる」変更は1件だけあります。それは新規・小規模アカウントの押し上げ（コールドスタート）の条件変更です（後述1）。** ランキングの計算式（`ScoringWeights`）の数値は22日連続で据え置きです。

- **① 新規・小規模アカウントの「お試し表示」の対象が広がり、同時に「48時間以内の投稿」という鮮度条件が全員に適用されました。これは既定オンの機能なので実挙動が変わります。**
  - Xには、**フォロワー1000人以下**のアカウントの**インプレッション1000未満**の投稿を、For You の**15〜16番目あたりのスコアまで人工的に引き上げる**仕組みがあります（`home-mixer/params/param.rs:641-663`、既定オン `rust_home_mixer_enable_viewer_cold_start_boost`：`param.rs:679-683`）。対象になるのは**リプライでもリポストでもない単独の投稿**だけです（`author_cold_start.rs:171-176`）。
  - **変更その1：投稿の鮮度上限が 24時間 → 48時間 に延長**されました（`param.rs:665-669`、86400秒→172800秒）。**投稿してから2日以内なら押し上げの対象**になります。
  - **変更その2：これまで鮮度条件は「Treatment（新方式）グループの閲覧者」にしか適用されていませんでしたが、今日から全グループに適用**されるようになりました（`author_cold_start.rs:299-301`）。「Control グループは投稿の古さを無視する」という挙動を検証していたテストが削除されています。
  - **意味するところ：** 閲覧者グループによって**有利・不利が違った状態が解消され、全員が「48時間以内」という同じ土俵**になりました。Treatment グループ側から見れば**24h→48hの緩和**、Control グループ側から見れば**無制限→48hの制約追加**です。**差し引きで、「3日前・1週間前の投稿が突然お試し表示される」ことはなくなり、代わりに「2日以内なら押し上げられる」窓が全員に開いた**と読めます。
  - **変更その3：Treatment グループの閲覧者に対して、「新しい検索方式（MoE）で拾ってきた候補であること」という条件が外れました**（`author_cold_start.rs:226-232`）。これまでは Treatment グループでは MoE 経由の候補しかお試し表示できませんでしたが、**今後はどの経路で拾われた候補でもよくなります**。**Treatment グループにおけるお試し表示の機会は実質的に増えます。**
  - **クリエイター側の行動指針：**
    - **フォロワー1000人以下の方は、投稿の「最初の48時間」がこれまで以上に勝負所**です。以前は（閲覧者グループによっては）古い投稿にもチャンスがありましたが、**48時間を過ぎた投稿はこの押し上げの対象外**になります。
    - **押し上げの対象は「リプライでもリポストでもない単独投稿」のみ**です。リプライ中心の運用では、この恩恵は受けられません。
    - **インプレッションが1000を超えると対象から外れます**（`param.rs:641-645`）。つまりこれは「まだ誰にも見られていない投稿を1回だけ試す」仕組みで、既に伸びた投稿をさらに伸ばすものではありません。

- **② 「クリックした後どれだけ読んだか」の評価方法が、昨日までの設計から作り直されました（後述2）。まだオフですが、方向性の転換として重要です。**
  - 9/16のレポートで報告した「クリック後滞在時間」の扱いについて、**わずか1日で設計が差し替え**られました。
  - **旧方式（削除）：** 「クリック後の滞在時間」の予測値に、**その投稿のいいね率が低いほど強いペナルティ**を掛ける方式（`ClickDwellLowFavRatePenalty*` の4パラメータ＋オンオフフラグ、計5つが**コードごと削除**：`param.rs` の旧426-453行相当）。
  - **新方式（追加）：** 「クリック後の滞在時間」の予測値に、**その投稿がクリックされる確率**を掛ける方式（`ranking_scorer.rs:246-255`）。新フラグ `rust_home_mixer_enable_cdwell_on_impr`、**既定オフ**（`param.rs:426-430`）。
  - **意味するところ（かみ砕くと）：** 旧方式は「**いいねされない投稿の滞在時間は割り引く**」＝**いいねを稼げない釣り投稿を叩く**発想でした。新方式は「**滞在時間 × クリック確率＝1回表示したときに期待できる読まれ時間**」＝**表示あたりの実効的な読まれ量**で評価する発想です。フラグ名の `on_impr`（＝per impression、表示あたり）がそれを示しています。
  - **クリエイター側への含意：** 評価軸が「いいねが伴うか」から「**そもそもクリックされるか × クリック後に読まれるか**」に移りました。**「いいねはされないが確実に開かれて読まれる投稿」（実用情報・解説・長文スレッド等）は、旧方式では割を食いましたが、新方式では正当に評価されます。** 逆に**「クリック率は高いが中身が薄い釣り」も「中身は濃いが誰も開かない投稿」も、どちらも不利**になります。
  - **ただし配信側の重みは 0.0 のままで、まだランキングに1ミリも効いていません**（`rust_home_mixer_cont_click_dwell_time_weight`：`param.rs:420-424`）。**新フラグも既定オフ**です。**重みが 0 から上がる日が転換点である**という9/16の見立ては変わりません。

- **③ 「いいねが多い投稿ほど、一部の人にわざと見せない」という新しい仕組みが追加されました（既定オフ・後述3）。**
  - `FavHoldoutFilter` という新フィルタが For You の候補生成パイプラインに組み込まれました（`home-mixer/filters/fav_holdout_filter.rs`、`phoenix_candidate_pipeline.rs:384`）。
  - **いいね数に応じて、その投稿を「見せない閲覧者の割合」が階段状に決まります**（`fav_holdout_filter.rs:10-34`）。いいね1以下は0%、2いいねで2%、10いいねで4%、100いいねで7%、1000いいねで13%、**3000いいね超で上限15%**。
  - 誰が外されるかは**投稿IDと閲覧者IDのハッシュで決定論的に決まる**ため（`inventory_holdout_filter.rs:31-47`）、同じ人には常に同じ投稿が見えません。ランダムに毎回変わるわけではありません。
  - **意味するところ：** これは**測定用のホールドアウト**（＝「もしこの投稿を見せなかったらどうなるか」を測るための対照群づくり）と読むのが自然です。人気投稿ほど多くの対照群が必要なため、いいね数に比例して割合が上がる設計になっています。**伸びている投稿にペナルティを与える意図の機能ではありません。**
  - **ただし有効化された場合の実影響：** **3000いいねを超えた投稿は、For You の候補から最大15%の閲覧者に対して消えます**。クリエイターから見ると**伸びている投稿のリーチが頭打ちになる**形で観測されます。**既定オフ**（`rust_home_mixer_enable_fav_holdout`：`param.rs:1000-1006`）であり、**有効化の予定・時期はコードからは読み取れません（要確認）。**

- **④ 返信スパム対策のフォロワー閾値が2つ動きました（後述4）。**
  - **Grok系とGemma系の分界点が 18万 → 20万フォロワー**に上がりました（`grox/flows/reply_spam/constants.py:8`）。18万〜20万帯域の返信欄の処理系統が入れ替わります。
  - **「連携スパム（coordinated spam）」検知の対象が 3万 → 5万フォロワー以下**に拡大しました（`grox/flows/reply_spam/task_filter.py:98`）。**これは取り締まりの範囲が広がる方向**です。3万〜5万フォロワーのアカウントの投稿に付く返信が、新たに連携スパム検知の対象になります。
  - あわせて、安全性ポリシーの種類に **`SpamManipulatedMedia`（加工メディアによるスパム）が追加**されました（`grox/flows/ptos/state.py:43`）。**分類の受け皿が増えただけで、どう判定・執行されるかはこのコードからは読み取れません（要確認）。**
  - **行動指針：** **3万〜5万フォロワー層の投稿の返信欄**では、複数アカウントによる似た返信の連投が検知されやすくなります。**相互に返信し合う運用（いわゆるエンゲージメント・グループ）はこの帯域で新たにリスク圏に入ります。**

- **⑤ 「なぜ自分の投稿が国別に非表示になったのか」をユーザーに開示する基盤が新設されました（既定オフ・後述5）。今日いちばん大きい"新設"です。**

  - **透明性レポート「Under the Hood」に、Takedown の行が出せるようになりました**（`under-the-hood/strato/columns/underTheHoodReport.User.strato:180-255`）。開示される文面まで具体的に書かれています。例：
    - 「LegalRequest(JP)」→ 説明「法的要請に応じて投稿が非表示にされました」／効果「**JP では、現地法に違反する投稿として X 上に表示されません**」（`underTheHoodLabels.strato:190-193`）。
    - 「Dmca」（投稿そのものへの著作権削除）→ 効果「**X 上に表示されません**」（同 `:213-217`）／「is_dmca」（投稿内メディアへの著作権削除）→ 効果「**非フォロワーへのおすすめから除外。表示される場合もメディアは利用不可**」（同 `:218-223`）。
    - 全世界コード（`xx`）の場合は「**X 上に表示されません**」と、国を限定しない文面に切り替わります（同 `:199-207`）。
  - アカウント単位の Takedown についても同様の文面が用意されました（`underTheHoodLabels.strato:226-249`）。
  - **意味するところ：** これまで「なんとなくリーチが落ちた」で終わっていた**法的削除・DMCA による国別非表示が、本人向けに明示される**ようになります。**ユーザーにとって明確にプラスの変更**です。

## 変更サマリ

1. **著者コールドスタート（フォロワー1000人以下の押し上げ）の条件を変更。** 鮮度上限 24h→48h、かつ**鮮度条件が Treatment アーム限定から全アーム適用に変更**。Treatment アームの候補条件から MoE 経由要件を削除。**既定オンの機能のため実挙動の変更あり。**
2. **クリック後滞在時間の合成方法を再設計。** 「いいね率ベースのペナルティ乗算」（5パラメータ）を**削除**し、「クリック確率との積＝表示あたり期待滞在時間」（`EnableCdwellOnImpr`）に**置換**。**既定オフ、かつ配信重みは 0.0 のままで挙動変更なし。**
3. **`FavHoldoutFilter` を新設。** いいね数に応じて 2%〜15% の閲覧者から投稿を決定論的に除外する測定用ホールドアウト。**既定オフ。**
4. **grox 返信スパム閾値2件。** Grok/Gemma 分界点 18万→20万、連携スパム検知の対象上限 3万→5万フォロワー（**取り締まり範囲の拡大**）。安全性ポリシーに `SpamManipulatedMedia` を追加。**実挙動の変更あり。**
5. **`takedowns/` モジュールと Under the Hood への Takedown 開示を新設。** 投稿単位・アカウント単位の法的削除理由を国コード付きで本人に開示する文面と集計ジョブ一式。**既定オフ。** あわせて未執行 Takedown を Gizmoduck 読み取りから伏せるフィルタを追加。
6. **推論 proto の列挙値変更。** `LLM_JUDGE_RELEVANT_TO_SEARCH` / `LLM_JUDGE_NOT_RELEVANT_TO_SEARCH`（107/108）を**削除**し、107 を `CLIENT_TWEET_LIVE_STREAM_REPLY`（ライブ配信への返信）に差し替え、108 は予約化。広告の遅延コンバージョンに Tier2/Tier3 の 20 種を追加（枠のみ）。
7. 挙動不変：可視性フィルタの twemcache 実装（11ファイル・約2600行）を共通 `xai_cache` クレートへ移管、`EvaluateTweets` RPC 枠の追加（未実装）、学習の `is_delayed_feedback`(bool) → `sample_source`(int8) 一般化、不正対策サービスの Kafka クラスタ `coredata`→`mltraining`、Phoenix の CUDA/埋め込みテーブル最適化。

## 変更点ごとの詳細：メカニズム → ユーザー/クリエイターへの影響

### 1. 著者コールドスタートの条件変更（**実挙動の変更あり**）

**メカニズム（コード根拠）**

`apply_cold_start` の絞り込み条件（`home-mixer/scorers/author_cold_start.rs:294-307`）が次のように変わりました。

変更前：
```rust
cold_start_base_eligible(c, params.follower_cap)
    && cold_start_corpus_eligible(arm, c, corpus[*i])
    && cold_start_freshness_eligible(arm, c, params.max_post_age)  // Treatment のみ適用
```
変更後（`author_cold_start.rs:298-301`）：
```rust
cold_start_base_eligible(c, params.follower_cap)
    && cold_start_corpus_eligible(arm, c, corpus[*i])
    && duration_since_creation_opt(c.tweet_id)
        .is_some_and(|age| age <= params.max_post_age)   // 全アームに適用
```

削除された `cold_start_freshness_eligible` は `if arm != ViewerArm::Treatment { return true; }` という早期リターンを持っており、**Treatment 以外は鮮度を一切見ていませんでした**。これが削除され、**全アームで `max_post_age` が効きます**。挙動が変わったことは、削除されたテスト `control_ignores_max_post_age`（Control で180分前の投稿が押し上げられることを検証していた）が**テストごと消えている**ことからも裏付けられます。

corpus 条件（`author_cold_start.rs:226-232`）：
```rust
ViewerArm::Treatment => corpus == AuthorCorpus::Treatment,   // 変更前: && is_phoenix_moe(c)
```
`is_phoenix_moe` は `served_type == ForYouPhoenixRetrievalMoe`（`author_cold_start.rs:167-169`）、すなわち MoE リトリーバル経由で拾われた候補かどうかです。テスト名も `treatment_viewer_cold_starts_treatment_moe_only` → `treatment_viewer_cold_starts_treatment_authors_only` に改名され、期待値が書き換わっています。

パラメータ（`home-mixer/params/param.rs:664-669`）：`rust_home_mixer_cold_start_max_post_age_secs` の既定値が `86400`（24時間）→ `172800`（48時間）。

前提条件（変更なし）：フォロワー1000人以下（`param.rs:658-663`）、ホーム上のインプレッション1000未満（`param.rs:640-645`）、リプライ・リポストでない（`author_cold_start.rs:171-176`）、押し上げ先は15〜16位相当のスコア（`param.rs:646-657`）。機能自体は既定オン（`param.rs:678-683`）。

**Xユーザー/クリエイターへの影響**

- **小規模アカウント（フォロワー1000人以下）：** 押し上げの窓が「投稿後48時間」に統一されました。**Treatment グループの閲覧者に対しては緩和（24h→48h）かつ対象候補の拡大**、**Control/Holdout グループの閲覧者に対しては制約の追加（無制限→48h）**です。総合的には**「投稿直後〜2日」に露出機会が集中し、それ以降は平坦化**します。
- **一般ユーザー（閲覧側）：** For You の15〜16番目付近に混ざる「見たことのない小規模アカウントの投稿」が、**より新しいものに揃う**方向です。数日前の投稿が突然出てくることは減ります。
- **影響を受けない層：** フォロワー1000人超のアカウント、リプライ/リポスト中心の運用、既に1000インプレッションを超えた投稿は、いずれもこの仕組みの対象外です。

**影響度：中**（既定オンの実挙動変更だが、押し上げは1リクエストにつき1投稿のみ・15〜16位相当という限定的な効果）

### 2. クリック後滞在時間の合成方法の再設計（既定オフ・重み0.0）

**メカニズム（コード根拠）**

`ScoringWeights` から5つのフィールドが削除され、1つに置換されました（`home-mixer/scorers/ranking_scorer.rs:34-38`）：

```rust
// 削除: enable_click_dwell_low_fav_rate_penalty, ..._baseline, ..._alpha, ..._floor, ..._cap
enable_cdwell_on_impr: bool,
```

計算式（`ranking_scorer.rs:246-255`）：
```rust
fn click_dwell_term(&self, scores: &PhoenixScores) -> Option<f64> {
    if !self.enable_cdwell_on_impr { return scores.click_dwell_time; }
    match (scores.click_dwell_time, scores.click_score) {
        (Some(cd), Some(click)) => Some(cd * click),
        ...
    }
}
```
旧実装は `cd * clamp((fav / baseline)^alpha, floor, cap)` という、**いいね予測値をベースライン0.01で正規化したものの冪乗**を乗じる形でした（旧 `baseline=0.01, alpha=0.5, floor=0.01, cap=1.0`）。

デバッグ用の可視化キーも `gate.click_dwell_low_fav_rate_penalty` → `gate.cdwell_on_impr` に変わりました（`ranking_scorer.rs:327-330`）。

最終合成での重み（`ranking_scorer.rs:481-484`）：`weights.cont_click_dwell_time` ＝ `rust_home_mixer_cont_click_dwell_time_weight`、**既定 0.0**（`param.rs:419-424`）。
