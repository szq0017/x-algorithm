## 非IT精通者向け・運用方法のまとめ（行動指針）

- **無断転載・著作権侵害の投稿は、今日から本当に消えます。** これまで Rust 版の可視性フィルタでは DMCA（著作権削除要請）や「全世界対象」の法的削除指定が事実上素通りしていましたが、今回そこが修正されました。他人の画像・動画・音楽を無断で載せる運用は、通報が通った時点でフィードから完全に消えます（本人の画面にだけは残るので「消えたことに気づかない」点に注意）。
- **逆に、正当な権利者の方は通報が効くようになりました。** 自分の作品が転載された場合、著作権通報の効果がこれまでより確実に出ます。
- **「大きなアカウントに返信 → その自分の返信にぶら下げて宣伝」は、今日から明確に処罰対象です。** 新設された「多段返信スパム検知」がスレッド全体を読み、自己連鎖のうち2件以上を宣伝目的と判断すると、その返信のスコアを **0点** に落とします。しかもこの経路は「スコアは下がらない」というこれまでの安全弁を通らないため、いったん良い点が付いていても 0 に落ちます。
- **上の検知の入口は「元投稿主のフォロワー1,000人以上」です。** 大きな話題への便乗リプライで宣伝を挟む戦術ほど、狙い撃ちされます。逆に小さなアカウントへの通常の連投返信は対象外です。
- **返信を連ねること自体は禁止ではありません。** ガードとして「最新の返信が問題視されなければ全部取り消し」「1件だけの指摘は破棄」が入っているので、普通のスレッド形式の長文投稿は影響を受けません。処罰されるのは「連鎖の複数投稿が宣伝／スパム」と判定されたときだけです。
- **フォロワーが非常に多いアカウントは、自動処罰の対象外である「絶対の上限」ができました。** 検知側が「信用度チェックを飛ばして処罰しろ」と指定しても、この上限を超えるアカウントには自動凍結もスパムラベル付与も適用されません。大アカウントほど自動処罰は届かず、人手審査頼みになります。
- **酒・薬・武器・ギャンブルなど「規制対象の話題」の投稿は、誤って制限されにくくなりました。** 二重チェックが実際に稼働し、意見が割れたら「違反なし」に倒れる作りです。一方で本当の違反の取りこぼしは増える方向なので、通報しても不発になるケースは増えます。
- **ブラジル在住・ブラジル政治の発信者は要注意です。** 2026年ブラジル選挙の候補者アカウント除外リストが 2,388 → **2,554 件（+166、解除ゼロ）** と過去最大の増え方をしました。該当アカウントの投稿は、フォロワー以外の「おすすめ」には出ません。
- **今日から広告IDと端末IDがフィード要求に載るようになりました。** 現時点で使い道はコードに現れていませんが、広告のコンバージョン紐付けや端末単位のパーソナライズの下ごしらえと読めます。
- **今日もランキング重み（何を評価してタイムラインを並べるか）は変わっていません。** 9日連続です。投稿内容の作り方を変える必要はありません。

### 1. DMCA・全世界テイクダウンが実際に効くようになった 【影響度：大】

**メカニズム**

`visibility-filtering/rules/context.rs:259-272` の `in_viewer_country` が書き換わりました。

変更前：
```rust

... .any(|c| c.eq_ignore_ascii_case(viewer_country))   // 国コードの literal 一致のみ
```

変更後：
```rust

... .any(|c| {
    c.eq_ignore_ascii_case(WORLDWIDE_COUNTRY_CODE)            // "xx"
        || c.eq_ignore_ascii_case(WORLDWIDE_COPYRIGHT_COUNTRY_CODE)  // "xy"
        || viewer_country.is_some_and(|v| c.eq_ignore_ascii_case(v))

```

あわせて `context.rs:291-298` の `legal_takedown_country` に一行追加：
```rust

```
（`WORLDWIDE_COPYRIGHT_COUNTRY_CODE = "xy"` は `context.rs:292` で新規定義）

つまり従来は、
- 「全世界対象（`xx`）」の法的削除は、閲覧者の国コードがたまたま文字列 `"xx"` のときしか一致せず → **実質的に誰にもドロップされていなかった**
- `TakedownReason::Dmca` は `legal_takedown_country` で `None` を返していた → **DMCA は一切ドロップされていなかった**
- 閲覧者の国コードが取れない要求（ログアウト・埋め込み等）では国別テイクダウンも全て不発

新しいゴールデンコーパスがこの新挙動をピン留めしています（`visibility-filtering/rules/golden_corpus.rs:578-626`）：
- `legal_takedown_worldwide_drops_for_us_viewer` / `..._without_viewer_country` → `DropLegalTakendownPostRule` でドロップ
- `local_laws_takedown_worldwide_drops_for_any_viewer` → `DropLocalLawsTakendownPostRule` でドロップ（傍観者通報 `BystanderReport` の全世界指定）
- `dmca_takedown_drops_for_any_viewer` → ドロップ
- `dmca_takedown_allows_author` → **著者本人には表示されたまま**（既存の著者免除がそのまま適用）

**Xユーザー/クリエイターへの影響**

- **権利者側（プラス）**：自分の写真・イラスト・動画・音源が無断転載された場合、著作権通報が通れば、その投稿は For You でもフォロー中でも他人の目に触れなくなります。これまでこの経路は無効でした。
- **転載アカウント側（マイナス）**：まとめ・切り抜き・リポスト系で他人の素材を使う運用は、1件の通報が通っただけでその投稿のリーチがゼロになります。**しかも自分の画面には見えたまま**なので「反応が急に止まった理由」に気づきにくい。インプレッションの急落を見たら、まず通報の有無を疑うべきです。
- **報道・言論（両面）**：各国の法的削除要請で「全世界」指定が付いたものは、今日から全ユーザーに対して非表示になります。誤った・過剰な削除要請が通った場合の影響範囲も、以前より広くなりました。
- **ログアウト閲覧・埋め込み**：国コードが取れない経路でも国別テイクダウンが効くようになった（`viewer_country.is_some_and(...)` は国別のみ、全世界指定は国不問）。9/01 の閲覧者ID正規化と同じく、ログアウト経路の穴が塞がる方向の継続です。

### 4. abuse-enforcement に「超高フォロワー」免除帯を新設 【影響度：中】

**メカニズム**

順序が保証されるようテストを追加（`rules.rs:683-691`）：
```rust

```

新テスト2件（`rules.rs:1285-1320`）：
- `baked_in_user_pipeline_splits_follower_bands_at_the_ceiling` — 250,000 → `very_high_follower_count`、50,000 → `high_follower_count`、500 → どちらでもない
- `baked_in_user_ceiling_ignores_skip_author_credibility_prechecks` — `f.score.skip_author_credibility_prechecks = true` でも 250,000 は `very_high_follower_count` で **スキップ**

`lib.rs:1967` でこの理由を「dedup/retention の対象外スキップ理由」の一覧にも追加。

**影響**

- 従来の `high_follower_count` は（本番設定側で）`skip_author_credibility_prechecks` フラグによる **突破が可能** な作りでした（そのパターンは `rules.rs:996-1020` のテスト用YAMLに現れます：`when: "cred.follower_count >= 12.34 && !score.skip_author_credibility_prechecks"`）。つまり検知器側が「このケースは信用度チェックを飛ばして処罰してよい」と指定すれば、フォロワーが多くても自動処罰が通っていました。
- 新しい `very_high_follower_count` にはその逃げ道がありません。**一定フォロワー数を超えたアカウントは、どの検知器が何を指定しても、自動のユーザー処罰（凍結・`SpamHighRecall` 等のラベル付与）が適用されません。**
- ユーザー体験としては、「大アカウントの明らかなスパム的挙動を通報しても自動処罰が動かない」現象が、以前より広い範囲で起こります。処罰は人手審査（9/03 に新設された XReview キューなど）に委ねられます。
- 中小アカウントには従来どおり自動処罰が適用され、大アカウントとの非対称性はさらに広がりました。
- **(要確認)** 公開ミラーでは両ルールとも `12.34` のモック値で、実際の閾値は GrowthBook 側（リポジトリ外）。テストが 250,000 / 50,000 を用いていることから、実値はその規模感である可能性がありますが、確定できません。またモック値が同一のため公開スナップショットのまま実行すると 50,000 のケースも `very_high` に一致するはずで、テストと公開YAMLの間に不整合があります（スクラビングの副作用と思われます）。
