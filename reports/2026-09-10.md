## 非IT精通者向け・運用方法のまとめ（行動指針）

- **今日の本命は「表示可否の判定ロジックの作り替え」です。** 投稿をタイムラインから消すかどうかの判断が、これまでの「消す理由が付いていたら消す」方式から、**安全性システムが返す『処分の種類』をそのまま尊重する方式**に変わりました（後述1）。
- **その結果、これまで巻き添えで消えていた投稿が残るようになります。** 安全性システムの処分には「削除(Drop)」「警告カバー(Interstitial)」のほかに「**Avoid（積極的には勧めない）**」「**Downrank（順位を下げる）**」という“中間の処分”があります。**これまでは中間処分でもFor You／フォロー中タイムラインから丸ごと消えていましたが、今日から残るようになりました。**
  - 心当たりのある人向け：センシティブ寄り・グレーゾーン判定を受けやすいアカウントの投稿が、**急にインプレッションが戻る／露出が増える**可能性があります。これは「アルゴリズムに好かれた」のではなく、**過剰に消していた挙動が是正された**結果です。
  - 逆にタイムラインを見る側は、**これまで見えなかったグレーゾーンの投稿が少し増える**方向になります。
  - なお、この「残るようになった投稿」に対して**順位を下げる処理は今回公開されたコードの中には見当たりません（要確認）**。「Downrank と書いてあるのに順位が下がらない」状態に見えるため、続報を待つべき箇所です。
- **一方で厳しくなった部分もあります。** 安全性システムから**返事が返ってこなかった投稿（未評価）は、これまで通り削除扱い**で確定しました。**安全性システムが不調なときは、あなたの投稿が消える**という設計（安全側に倒す）は維持されています。
- **返信ツリー・引用リポストの巻き添えルールも同じ基準に揃いました。** 引用先やリポスト元、会話の親投稿が「中間処分」なだけなら、**あなたの投稿は巻き添えで消えなくなりました**。ただし引用先が「削除」または「墓標(Tombstone)」処分なら、**従来どおりあなたの投稿ごと消えます**。**グレーな投稿の引用リポストのリスクは下がり、明確にアウトな投稿の引用リポストのリスクは変わりません。**
- **タイムラインに「投稿の形をしていない広告」が入るようになりました（後述2）。** 大きな横長画像＋見出し＋本文＋ボタン（最大2つ）で構成される**バナー型広告**です。ポストではないので、**リプライ・リポスト・いいねの対象になりません**。押すと消える設定も可能です。**「広告に返信して晒す」「引用RTでツッコむ」といった従来の反応ができない広告**が今後増える可能性があります。
- **動画・ライブ配信の成人向けコンテンツ審査が広がりました（後述3）。**
  - これまで**いいね64件未満の投稿は冒頭10秒の再審査が免除**されていましたが、この免除が撤廃されました。**過去に成人向け判定を受けたことがあるアカウントは、いいねがほとんど付いていない投稿でも冒頭10秒の再審査が走ります。**
  - **ライブ配信（ブロードキャスト）が新たに審査対象**になりました。しかも動画に課されていた「30秒以上」という長さ条件がなく、**配信であれば長さを問わず冒頭10秒がチェックされます**。
  - 行動指針：**動画・配信の冒頭だけ健全に見せて中身を差し替える手口は、小規模アカウント・ライブ配信を含めてほぼ塞がりました。**
- **推薦モデルが「画像・動画の中身そのもの」を数値として受け取るのをやめました（後述4）。** 主力ランキングモデルの学習設定から**マルチモーダル投稿埋め込み（v5）が外され、登録されている全ランキング設定でオフ**になりました。今後は視覚的な内容は、AI(Grox)による注釈や反応実績を通じて間接的に評価されます。**「画像・動画の見た目の良さを直接モデルが読む」路線は少なくとも一旦停止**です（実運用への反映は再学習が前提＝要確認）。
- **ブロックの向きが正しく記録されるようになりました。** これまで「自分が相手をブロックした」ケースが「相手が自分をブロックした」と誤ってラベル付けされていました。**表示される／されないの結果は従来と同じ**（どちらも非表示）で、内部記録の正確性の修正です。

## 変更サマリ

1. 可視性判定（VF）を**「理由(FilteredReason)ベース」から「処分(Action)ベース」へ全面的に作り替え**。`Avoid` / `Downrank` は**削除されなくなり**、`Tombstone` / `NotEvaluated` は削除。返信ツリー・引用・リポストの巻き添え判定も同じ基準に統一。
2. 広告描画に**新フォーマット「Header Image Prompt Ad」**を新設（バナー型・非ポスト・CTAボタン最大2個・タップで消える設定あり）。他のどの広告形式よりも優先して選ばれる。
3. 成人向けコンテンツの「冒頭10秒クロップ再判定」フローが、**いいね64件未満の免除を撤廃**し、**ライブ配信（ブロードキャスト）を新たに対象化**（配信は長さ条件なし）。sex/nudity 判定モデルも配信フレームを受け取れるように拡張（既定オフ）。
4. Phoenix 主力ランキング設定 `xrecsys_seqpack` から**マルチモーダル投稿埋め込み `v5` を削除**。登録済みランキング設定は全てオフに。曜日特徴 `local_day_of_week` に on/off スイッチを新設（既定 True ＝ 現状の挙動は不変）。
5. ブロック方向の取り違え修正：新しい理由コード `ViewerBlocksAuthor` を追加し、「自分が相手をブロック」に正しく割り当て。
6. その他は挙動不変の基盤系：`quiet-spans` 機能のログ出力削除、NUMA ピン留めを `numa.schedule` から `os.sched_setaffinity` へ置換（isolated CPU を除外）。`param.rs` の同期日時のみ更新（**フィーチャースイッチの既定値変更はゼロ**）。

## 変更点ごとの詳細（メカニズム → Xユーザー／クリエイターへの影響）

### 1. 可視性判定を「処分ベース」に作り替え（影響度：**大**）

**メカニズム**

これまで `VFFilter` は「投稿に非表示理由が付いているか」で消していました（旧 `should_drop`）。理由が `SafetyResult` 型なら中の action を見ますが、**それ以外の理由（NSFWメディア、著者が危険、報告済み投稿…）が付いていれば無条件に削除**でした。

新しい実装は、候補に `visibility_action` フィールド（`home-mixer/models/candidate.rs:57`）を持たせ、**処分の種類だけで判断**します。

`home-mixer/filters/vf_filter.rs:22-27`：

```rust
pub(crate) fn should_drop_action(action: &Action) -> bool {
    match action {
        Action::Allow | Action::Interstitial | Action::Avoid | Action::Downrank => false,
        Action::Drop(_) | Action::Tombstone | Action::NotEvaluated => true,
    }
}
```

処分の種類は `visibility-filtering-client/models.rs:58-67` の 7 値（`NotEvaluated` / `Allow` / `Drop` / `Interstitial` / `Downrank` / `Tombstone` / `Avoid`）で、gRPC のワイヤ上も全て定義済みです（`models.rs:405-417`）。

旧実装との差分を、実際に走るパス（`EnableXaiVfClient` は既定 `true`＝`param.rs:1161-1165`、つまり新 gRPC クライアント経路）で比べると：

| VFサービスの処分 | 旧挙動 | 新挙動 |
|---|---|---|
| `Allow` | 残す | 残す |
| `Interstitial`（警告カバー） | 残す | 残す |
| **`Avoid`** | **削除** | **残す** |
| **`Downrank`** | **削除** | **残す** |
| `Drop` | 削除 | 削除 |
| `Tombstone` | 削除 | 削除 |
| `NotEvaluated`（応答なし・未評価） | 削除 | 削除 |

旧コードでは `Avoid` / `Downrank` の場合も `result_to_reason` が `filtered_reason` をそのまま理由として詰めていたため、旧 `should_drop` の `Some(_) => true` に落ちて削除されていました。この分岐が今回まるごと削除されています（`visibility-filtering-client/vf_client.rs` の `result_to_reason` 関数が削除、`result_to_visibility` は `action` と `reason` を別々に保持する形へ：`vf_client.rs:348-357`）。

VFサービスから応答が返らなかった投稿には `Action::NotEvaluated` が入り（`vf_client.rs:360-376`）、`should_drop_action` で削除されます。**安全側に倒す（fail closed）設計は維持**されています。ただしテストの説明文は "missing response ids fail closed" から "missing response ids surface no verdict" に書き換えられており（`vf_client.rs:762`, `840-846`）、意図としては「判定なしを表現できるようにした」という位置づけです。

巻き添え判定（返信ツリーの親／引用先／リポスト元）も同じ関数を使うようになりました（`home-mixer/candidate_hydrators/vf_candidate_hydrator.rs:140-169`）。旧実装の `should_drop_reason` は `_ => true`、つまり**`SafetyResult` 以外の理由なら親／引用先が何であれ巻き添えで削除**していました。テストにも明示されています（`vf_candidate_hydrator.rs:288-302`）：引用先が `Drop` → 巻き添え削除、`Tombstone` → 巻き添え削除、**`Avoid` → 巻き添えにしない**。

なお旧 Strato 経路（`EnableXaiVfClient=false` のフォールバック）については `action_from_strato_reason`（`vf_client.rs:178-187`）が新設され、`SafetyResult{action: NotEvaluated}` は `Allow`、`SafetyResult` 以外の理由は `Drop` にマップされます。**旧経路では「未評価＝許可（fail open）」、新経路では「未評価＝削除（fail closed）」**と、2つの経路で安全側の倒し方が逆になっている点は注意が必要です（既定は新経路なので実運用は fail closed）。

クライアントに返す理由コードの見え方は `to_visibility_reason()`（`vf_client.rs:116-133`）で従来形式に射影され、`Allow` → 理由なし、`Interstitial` → `SafetyResult(Interstitial)`、それ以外 → 生の理由、となります。この値は `home-mixer/scored_posts_server.rs:98` からクライアントに送られます。

**Xユーザー／クリエイターへの影響**

- **影響度：大。** グレーゾーン判定（`Avoid` / `Downrank`）を受けている投稿・アカウントが、**For You とフォロー中タイムラインの両方に戻ってきます**。これまでは中間処分でも実質「完全削除」と同じ扱いでした。
- **影響を受ける層**：センシティブ／政治／アダルト境界／低品質判定を受けやすいアカウント。心当たりのある発信者は、**数日〜数週間かけてリーチが回復方向に動く**可能性があります。
- **引用リポスト・返信で絡む側のリスクが下がりました。** グレーな投稿を引用しても、それが `Drop`/`Tombstone` でない限り自分の投稿は巻き添えにならなくなりました。明確にアウトな投稿（`Drop`/`Tombstone`）の引用は従来どおり自分の投稿ごと消えます。
- **タイムラインを見る側**：グレーゾーンの投稿の露出が増える方向。ただし `Interstitial`（警告カバー）は従来どおり付きます。

### 2. 新広告フォーマット「Header Image Prompt Ad」（影響度：**中〜大**、ただし配信有無は要確認）

**メカニズム**

`home-mixer/util/urt/ad_marshaller.rs:42-50` で、広告に `header_image_prompt_ad_info` が付いていれば**他のどの広告形式よりも先に**この新形式で描画されます（SSP広告／RTB画像広告／通常のプロモポストの判定より前）。

生成される中身（`ad_marshaller.rs:223-311`）：

- タイムライン項目の種別が `TimelineItemContent::Message`（＝**ポストではない**「メッセージプロンプト」）。エントリID名前空間は `header-image-prompt-ad`（`ad_marshaller.rs:29, 301`）。
- 構成要素：ヘッダー画像1枚（幅・高さ指定、テストでは 1199×571 の横長）、見出しテキスト、本文テキスト、**主ボタン**（テキスト＋遷移先URL＋`primary_cta` イベント）、**副ボタン**（`secondary_button_text` が空でなければ生成、`secondary_cta`）。
- `dismiss_on_click`：広告側の設定で、**タップすると項目が消える**挙動を指定できます（`ad_marshaller.rs:249`）。
- 計測：表示時に `impression_callback_endpoints`、クリック時に `click_callback_endpoints` へコールバック（`ad_marshaller.rs:296-298`, `to_callbacks` は `ad_marshaller.rs:314-326`）。

通常のプロモポスト経路と違い、**`promoted_metadata`（プロモ表示メタデータ）も `contextual_tweet_ref` も付きません**。ポスト本体が存在しないため、投稿としてのIDを持ちません。

**Xユーザー／クリエイターへの影響**

- **影響度：中〜大（ただし実際に配信されているかはコードからは不明＝要確認）。** タイムラインに**バナー広告**が混ざる構造が入りました。
- **ユーザー行動への直接的な影響**：この広告は**ポストではないため、リプライ・引用リポスト・いいね・ブックマークの対象になりません**。「広告に大喜利リプをつける」「引用RTでツッコむ」という、Xで長年見られてきた広告への反応行動が、この形式では成立しません。広告主にとっては炎上リスクが下がり、ユーザーにとっては公開の場での反論手段が減ります。
- `dismiss_on_click` により**タップ＝消える**動線が用意されているため、誤タップで広告が消えて遷移する（＝クリック計上される）ケースが起きうる形です。
- **クリエイターへの影響**：タイムライン内の広告枠が、従来の「プロモ投稿」だけでなく非ポスト型でも埋まりうるようになりました。ただし**広告挿入密度そのもの（`home-mixer/ads/`）は今回変更されていません**ので、「広告が増える」とは断定できません（要確認）。

### 3. 成人向けコンテンツ審査の対象拡大：低エンゲージメント投稿とライブ配信（影響度：**中**）

**メカニズム**

「長尺動画の冒頭10秒を切り出して成人向けコンテンツを再判定する」フロー（前回 2026-09-09 レポートで報告）の対象条件が緩和されました。

`grox/flows/ptos/task_safety_ptos_adult_content_leading_frames_filter.py` から、以下の足切りが**削除**されました：

```python
# 削除された条件
if post.get_fav_count() < grox_config.media_hydration.deluxe_fav_count_threshold:  # 64
    return cls._skip(post, "not_high_fav")
```

残っている足切りは「**過去に成人向け違反の注釈がない、かつ、いいねが512件未満なら対象外**」のみです（同ファイル `:60-65`、定数 `ADULT_CONTENT_LEADING_FRAMES_UNCONDITIONAL_FAV = 512` は `grox/flows/ptos/constants.py:33`）。

条件を整理すると：

| | 変更前 | 変更後 |
|---|---|---|
| 過去に成人向け判定あり | いいね **64件以上**で対象 | **いいね数に関係なく対象** |
| 過去に成人向け判定なし | いいね 512件以上で対象 | いいね 512件以上で対象（変更なし） |

さらに**ライブ配信（ブロードキャスト）が新たに対象**になりました（同ファイル `:44-51`）：

```python
broadcasts = [
    p.broadcast_metadata
    for p in (post, post.quoted_post)
    if p is not None and p.broadcast_metadata is not None and p.broadcast_metadata.broadcast_id
]
if not long_videos and not broadcasts:
    return cls._skip(post, "no_long_video")
```

動画には `ADULT_CONTENT_LEADING_FRAMES_MIN_DURATION_SECONDS = 30.0` 秒以上という条件がありますが、**配信にはこの長さ条件がありません**。対象になった配信には動画と同じく `crop_seconds = 10.0` が設定されます（同ファイル `:70-72`）。

判定側の sex/nudity モデル呼び出しも配信フレームを受け付けるよう拡張されました（`grox/flows/ptos/task_safety_ptos_safemodel_sex_nudity.py:32, 86-89, 158-165, 177-184`）。ただしこれは `enable_local_broadcast_frame_extraction`（`grox/config/config.py:115`、**既定 `False`**）で保護されています。配信フレームの取得経路も、外部の `grox-fetcher` からローカルの `BroadcastLoader` に切り替えられるようになりました（`grox/core/data_loaders/media_loader.py:520-590`、同じく既定オフ）。

**Xユーザー／クリエイターへの影響**

- **影響度：中。** 「冒頭だけ健全にして中身を差し替える」手口への対策が、**小規模アカウントとライブ配信に拡張**されました。
- **影響を受ける層**：
  - **過去に一度でも成人向け違反の注釈が付いたアカウント**。以前は「いいね64件未満なら再審査されない」という抜け道がありましたが、これが消えました。**通報されにくい小さな投稿でも継続的に審査されます。**
  - **ライブ配信を行うアカウント**。配信は長さを問わず冒頭10秒がチェック対象になりました。
- 逆に、**過去に成人向け違反歴がなく、いいねが512件未満の投稿**については、条件は何も変わっていません（依然として対象外）。一般ユーザーへの影響はありません。
- 配信フレームを実際にAI判定に流す部分（`enable_local_broadcast_frame_extraction`）は**既定オフ**なので、今日時点でどこまで実運用されているかは**要確認**です。対象判定（`crop_seconds` の設定）まではフラグなしで動きます。

### 4. ランキングモデルからマルチモーダル投稿埋め込みを撤去（影響度：**中**、再学習前提＝要確認）

**メカニズム**

主力ランキング学習設定 `xrecsys_seqpack`（`phoenix/xrex/configs/xrecsys.py:358` 以降のブロック）から、以下の1行が削除されました：

```python
"multimodal_embedding_type": "v5",   # ← 削除
```

`phoenix/README.md` の表も更新されており、`Multimodal post embedding` の欄は「v5 on `xrecsys_seqpack`; off on `home_direct_packed`」から「**off (`home_direct_packed` and `xrecsys_seqpack`)**」に、本文も「`xrecsys_seqpack` だけで有効」から「**登録されている全てのランキング設定でオフ**」に書き換わりました（`phoenix/README.md:412, 425-426`）。

なお `v5` 自体は生成推薦（`phoenix/xrex/configs/xrecsys_gen_recs.py:123, 260`）では引き続き使われており、機能ごと廃止されたわけではありません。

あわせて、曜日の文脈特徴 `local_day_of_week` に on/off スイッチが新設されました（`phoenix/xrex/models/recsys_model.py:288` の `enable_day_of_week: bool = True`、適用は `:2002-2004`）。**既定 `True` なので現時点の挙動は変わりません**が、この特徴を切って評価する実験の準備が入ったことを意味します。

**Xユーザー／クリエイターへの影響**

## 不確実な点（要確認）

1. **`Avoid` / `Downrank` の実際の発生頻度が不明。** 本リポジトリの Rust 版ルールエンジン（`visibility-filtering/rules/`）が出す処分は `Allow` / `Drop` / `Interstitial` の3種のみで、`Avoid` / `Downrank` は `reference_compare.rs`（旧システムとの照合用）にしか現れません。ワイヤ上は定義済み（`models.rs:405-417`）なので、**実サービスの VF サービスがこれらを返しているかどうかで影響の大きさが変わります**。返していなければ変更1の実効影響はゼロに近く、返していれば大きな緩和になります。
2. **`Downrank` に対する順位下げ処理が今回公開範囲に見当たりません。** `Action::Downrank` を消費してスコアに罰則を与えるコードは `home-mixer/` 内に存在しません（`should_drop_action` の分岐以外は `reference_compare.rs` のみ）。「残すが順位を下げる」という意図が実際に実装されているのか、別レイヤーにあるのか、未実装なのかは不明です。
3. **`Interstitial`（警告カバー）の見え方の変化。** `Avoid` / `Downrank` の投稿は残りますが、クライアントには `to_visibility_reason()`（`vf_client.rs:116-133`）経由で生の理由コード（例：`ContainNsfwMedia`）が渡ります。クライアントがこれを見て警告カバーを出すのか、そのまま表示するのかは本リポジトリ外の実装次第です。
4. **新広告フォーマットが実配信されているか不明。** `header_image_prompt_ad_info` を広告に付ける側（広告選定・入稿）のコードは本リポジトリに含まれていません。描画側の準備が整った、という段階の可能性があります。
5. **新広告フォーマットへのブランドセーフティ適用範囲が不明。** この項目はポストではないため、投稿候補に対する可視性フィルタ（変更1）の対象外です。広告側のブランドセーフティ（`home-mixer/ads/`、今回変更なし）でカバーされている想定ですが、コードからは確認できません。
6. **マルチモーダル埋め込み撤去が本番モデルに反映される時期。** 学習設定の変更であり、再学習・評価・デプロイを経る必要があります。撤去理由（品質劣化・コスト・v6/v8 への移行準備など）もコードからは読み取れません。
7. **旧 Strato 経路と新 gRPC 経路で「未評価」の扱いが逆（fail open / fail closed）。** 既定は新経路（`EnableXaiVfClient = true`）ですが、フォールバック時に安全側の挙動が反転する設計が意図的かどうかは不明です。
8. **`enable_day_of_week` スイッチ新設の意図。** 既定 `True` で挙動は不変ですが、曜日特徴を外す実験が予定されている可能性があります。
