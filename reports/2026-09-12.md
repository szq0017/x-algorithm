## 非IT精通者向け・運用方法のまとめ（行動指針）

- **今日もランキング（並び順）の計算式そのものは変わっていません。** 17日連続で `ScoringWeights` の数値は据え置きです。変わったのは「並べ終えたあとに何を間引くか」「どの投稿を国ごとに隠すか」という**周辺の仕組み**です。

- **① 「似た投稿を弾く仕組み」に、新しい入り口ができました（後述1）。**
  - Xは For You のランキング後段で **DPP という多様性フィルタ**を通しています。これは「上位150件の中で、内容ベクトルが似すぎている投稿を落として、話題が偏らないようにする」装置です。落とされた投稿は**スコアが 0 にされ、事実上タイムラインの最後尾に沈みます**（`vm-ranker/scoring/dpp_model.rs:170-180`）。
  - 今回、この装置に **「シード（起点）投稿」を1件渡せる機能**が追加されました。シードを渡すと、**そのシード投稿に似ている候補が優先的に間引かれます**。しかも**シードは150件の枠を消費しない**設計です（`vm-ranker/dpp.rs:95-141`）。
  - **意味するところ：** 「いまユーザーが見ている（あるいは直前に見た）1件の投稿と、そっくりな投稿を続けて出さない」ための土台です。**同じニュース・同じミーム・同じ切り抜き動画が連続して流れる現象を減らす方向**の改修と読めます。
  - **ただし現時点では For You では動いていません。** For You からの呼び出し側コード（`home-mixer/scorers/vm_ranker.rs:107-114`）は**シードを一切設定していません**（`..Default::default()` のまま＝0）。つまり**今日の時点では機能は「配線待ち」**です。どの画面で使われるか（投稿詳細の「関連する投稿」、縦型動画の連続再生、など）は**このコードからは特定できません（要確認）**。
  - **クリエイター側の行動指針：** **同一テーマ・同一素材の投稿を短時間に連投すると、将来的に2件目以降が間引かれるリスクが上がる**方向です。連投するなら**切り口・画像・文面を実質的に変える**ほうが安全です。逆に、**他人の投稿と内容ベクトルが近いだけの「後追い投稿」も不利**になりやすくなります。

- **② 「全世界で非表示」の適用範囲が狭まりました（後述2）。過去に消えていた投稿が戻る可能性があります。**
  - Xは投稿に「テイクダウン理由」を付けて、国ごとに非表示にします。国コードには特殊値があり、**`xx` = 全世界、`xy` = 全世界（著作権）** です。
  - 今日の変更で、**次の2ケースが「全世界非表示」から外れました**。
    1. **「法的要請」理由で国コードが `xy`（＝著作権の全世界コード）だったもの → 非表示にしない**（`visibility-filtering/rules/context.rs:296-302`）。
    2. **「第三者からの通報（BystanderReport）」理由で国コードが `xx` / `xy` だったもの → 非表示にしない**（`visibility-filtering/rules/context.rs:310-317`）。
  - **一方で、本物の DMCA（著作権削除）は今まで通り全世界で非表示のままです**（`TakedownReason::Dmca` は引き続き `xy` 扱い）。「理由未指定」の全世界テイクダウンも今まで通り非表示です。
  - **つまり「理由コードの付け方がおかしかった記録のせいで、世界中で消えていた投稿」だけが救済される**、という整理です。**心当たりのあるクリエイターは、過去に消えた投稿の復活を確認する価値があります**（復活が遡及適用されるかは**要確認**）。
  - **注意：** これは**規約違反の取り締まりが緩んだという話ではありません**。DMCA・法的要請（国指定あり）・成人向け判定などは一切変わっていません。

- **③ ブラジル2026年選挙フィルタの対象が 2,554 → 2,707 アカウントに拡大しました（後述3）。**
  - このフィルタは**候補者本人が申告したアカウント**を、**フォローしていない人の For You から除外**する仕組みです（選挙期間中の公平性対応）。
  - 今回 **163件追加・10件削除、差し引き +153件**。**フィルタの判定ロジック自体は一文字も変わっていません**（リストの中身だけの更新）。
  - **ブラジルの政治アカウント運用者への行動指針：** **リスト入りすると、フォロワー以外へのリーチが構造的に落ちます。** 逆に**フォロワーへのリーチは維持される**ので、選挙期間中は**フォロワー獲得と、DM・コミュニティ等のフォロワー内チャネル**に重心を移すのが合理的です。

- **④ 検索の「関連性」を AI が採点する枠が予約されました（後述4）。**
  - 行動シグナルの一覧に **`LLM_JUDGE_RELEVANT_TO_SEARCH`(107) / `LLM_JUDGE_NOT_RELEVANT_TO_SEARCH`(108)** が追加されました。これまでは**人間ユーザーのクリック等から関連性を推定**していましたが、**大規模言語モデルが「この投稿は検索語に関連するか」を判定した結果**を、学習シグナルとして扱う準備です。
  - **現時点では枠の予約のみ**で、学習側の定数表（`phoenix/xrex/data/recsys/constants.py`）にもランキング重みにも登場しません（**要確認**）。
  - **方向性としては、「検索語を大量に詰め込んで釣る」タイプの投稿が不利になる**改修です。

- **⑤ 透明性レポート「Under the Hood」が社員にも開放されました（後述5）。** 閲覧許可ロールに `employee` が追加され、表示対象月に上限をかけるスイッチも新設。**社内ドッグフーディング段階＝一般公開に一歩近づいた**と読めます。

- **⑥ 動画の「動かすと見えてくるもの」検査が、誤検知を減らす方向に調整されました（後述6）。** 前回（9/11）強化された機能の**精度チューニング**です。**健全な動画が誤って安全性レビューに回される確率が下がります**（この機能自体は既定オフ＝要確認）。

- **⑦ 残りは基盤整備で、ユーザー体験への直接の影響はありません。** スコアのログ形式を Thrift から Protobuf へ二重書き込みに移行（後述7）、可視性フィルタの接続方式を xDS へ移行、学習データ用 Kafka の認証を mTLS 対応。

## 変更サマリ

1. **多様性フィルタ DPP に「シード投稿」を1件ピン留めできる機能を追加。** シードに似た候補を優先的に間引き、かつシードは `top_k`（既定150）の枠を消費しない。**For You からは未配線（シード未設定）**。
2. **全世界テイクダウンの範囲を縮小。** 「法的要請 × `xy`」と「第三者通報 × `xx`/`xy`」が全世界非表示の対象外に。DMCA と「理由未指定 × 全世界」は従来通り非表示。
3. **ブラジル2026選挙フィルタの対象アカウントを 2,554 → 2,707 に拡大**（+163 / −10）。判定ロジックの変更なし。
4. **Phoenix proto に LLM 判定由来の検索関連性アクション 2種（107/108）を追加**、および推論応答に `requestedActionLogits`（要求アクションのロジットを配列で返す軽量形式）を追加。
5. **Under the Hood（透明性レポート）の閲覧ロールに `employee` を追加**、表示対象月の上限を切る FS `under_the_hood_report_max_month_bucket` を新設（既定 0＝上限なし）。
6. **Grox 動画「モーションリビール」解析の誤検知対策**：平坦な背景（勾配が小さい画面）では位置合わせを丸ごとスキップ、位置合わせ結果が大きすぎる場合（平行移動 >15%、線形成分 >0.15）は棄却。
7. **スコアログを Protobuf 形式で新トピックへ二重書き込み開始**（`LoggedScoredCandidate` / `LOGGED_SCORED_CANDIDATES_TOPIC`）。既存 Thrift 出力も並行して継続。
8. 挙動不変の基盤系：著者特徴量の 64bit パック表現追加（`dead_code` 扱いで未接続）、可視性フィルタの TES/Gizmoduck 接続を xDS へ移行、学習データ用 Kafka の mTLS 認証対応。

## 変更点ごとの詳細（メカニズム → Xユーザー／クリエイターへの影響）

### 1. DPP 多様性フィルタに「シード投稿」機能を追加（影響度：**大**／ただし現時点は未配線）

**メカニズム**

`rescore` の引数に `seed: Option<&DppInput>` が追加されました。

`vm-ranker/dpp.rs:35-40`：
```rust
pub fn rescore(
    inputs: &[DppInput],
    seed: Option<&DppInput>,
    config: &DppConfig,
    _viewer_id: u64,
) -> Vec<DppResult> {
```

シードは候補配列の末尾（インデックス `m`）に「仮想的な候補」として連結され、**品質スコア `q` は常に 1.0（＝最大品質）扱い**になります。

`vm-ranker/dpp.rs:106-113`：
```rust
let total = m + usize::from(seed.is_some());
let qf: Vec<f64> = (0..total)
    .map(|ki| {
        let q = if ki < m { item_at(ki).score / max_score } else { 1.0 };
        (alpha * q).exp()
    })
    .collect();
```

そのうえで貪欲 DPP の**1番目の選択をシードに固定（ピン留め）**します。

`vm-ranker/dpp.rs:223-245`：
```rust
fn greedy_dpp(kernel: &[f64], n: usize, k: usize, pinned_first: Option<usize>) -> GreedyDppResult {
    ...
    let max_items = match pinned {
        Some(_) => (k + 1).min(n),   // シードは top_k の枠を食わない
        None => k.min(n),
    };
    let (first, first_val) = match pinned {
        Some(p) => (p, kernel[p * n + p]),   // 最初の1件をシードに固定
        ...
```

DPP の貪欲選択は「既に選んだものとの類似度が高いほど、次に選ばれにくい」性質を持つため、**1件目をシードに固定すると、以降の選択がシードとの非類似度を最大化する方向に働きます**。最後にシードは結果から取り除かれます（`vm-ranker/dpp.rs:133-141`）。

テストがこの意図を明示しています。`vm-ranker/dpp.rs:489-516`：
```rust
let result = rescore(&inputs, Some(&seed), &config, 0);
assert!(!ids.contains(&1), "seed near-duplicate should be suppressed, got {ids:?}");
assert!(ids.contains(&2), "orthogonal candidate should survive");
assert!(!ids.contains(&999), "seed itself never returned");
```

シードの埋め込みベクトルは埋め込みストアから引かれ、**見つからなければシードなしで従来通り動作**します（`vm-ranker/scoring/dpp_model.rs:85-107`）。見つかったか否かは新規メトリクス `vm_ranker_dpp_seed_context_total{result="pinned"|"embedding_missing"}` で計測されます（`vm-ranker/metrics.rs:52-59`）。

**「間引かれる」とは何が起きるか**

DPP で選ばれなかった候補は**スコアを 0 にされて返されます**。

`vm-ranker/scoring/dpp_model.rs:170-180`：
```rust
req.candidates.iter().map(|c| RankedCandidate {
    tweet_id: c.tweet_id,
    score: if selected_ids.contains(&c.tweet_id) { c.score.unwrap_or(0.0) } else { 0.0 },
}).collect()
```

`home-mixer` 側はこのスコアをそのまま採用するため（`home-mixer/scorers/vm_ranker.rs:66-79`）、**落選＝実質的にタイムラインの最下層へ**という扱いになります。

**現時点の稼働状況**

- DPP 自体は**既定で有効**：`EnableVMRanker` = `true`、`VMRankerDppTheta` = `0.65`、`VMRankerDppMaxSelectedRank` = `150`（`home-mixer/params/param.rs:623-657`）。
- しかし**シードは For You から渡されていません**。`home-mixer/scorers/vm_ranker.rs:107-114` の `RankRequest` 構築は `viewer_id` / `candidates` / `value_model_id` / `dpp_params` のみを設定し、残りは `..Default::default()`（＝`seed_tweet_id` は 0）。`dpp_model.rs:86` の `if req.seed_tweet_id == 0 { return None; }` により**シード経路は起動しません**。
- なお `xai_vm_ranker_proto` のスキーマ定義はこの公開リポジトリに含まれていないため、**`seed_tweet_id` がどの呼び出し元から設定される想定かはコードからは確認できません（要確認）**。

**Xユーザー／クリエイターへの影響**

- **一般ユーザー：** 配線後は、**「いま見ている投稿と激似の投稿」が後続に並びにくくなります**。同じ事件の同じ映像、同じ画像のリポスト違い、同じ切り抜きが連続する体験が減る方向です。
- **クリエイター：** **同一テーマ・同一素材の連投の2件目以降が不利**になります。特に**トレンドに対する「みんなが書くのと同じ内容」の投稿**は、先行する類似投稿をシードにされた時点で落選しやすくなります。**独自の切り口・独自の素材の価値が上がる**改修です。
- **影響の時期は未定です。** 今日の時点で For You の並びは変わりません。

### 2. 全世界テイクダウンの範囲を縮小（影響度：**中**）

**メカニズム**

可視性フィルタは投稿に付いた「テイクダウン理由 + 国コード」を見て、**閲覧者の国と一致する場合、または国コードが全世界コード（`xx` / `xy`）の場合に投稿を落とします**。

`visibility-filtering/rules/context.rs:260-270`：
```rust
fn in_viewer_country(&self, extractor: fn(&TakedownReason) -> Option<&str>) -> bool {
    ...
    .any(|c| {
        is_worldwide_code(c) || viewer_country.is_some_and(|v| c.eq_ignore_ascii_case(v))
    })
}
```

今回、**抽出関数 `extractor` の側に例外が2つ入りました**。

**(a) 法的要請 × `xy`（著作権の全世界コード）を無視** — `visibility-filtering/rules/context.rs:296-307`：
```rust
fn legal_takedown_country(reason: &TakedownReason) -> Option<&str> {
    match reason {
        TakedownReason::LegalRequest { country_code }
            if country_code.eq_ignore_ascii_case(WORLDWIDE_COPYRIGHT_COUNTRY_CODE) =>
        {
            None                                    // ← 新規：判定対象から除外
        }
        TakedownReason::LegalRequest { country_code }
        | TakedownReason::UnspecifiedReason { country_code } => Some(country_code),
        TakedownReason::Dmca => Some(WORLDWIDE_COPYRIGHT_COUNTRY_CODE),
        _ => None,
    }
}
```

**(b) 第三者通報 × 全世界コードを無視** — `visibility-filtering/rules/context.rs:310-317`：
```rust
fn local_laws_takedown_country(reason: &TakedownReason) -> Option<&str> {
    match reason {
        TakedownReason::BystanderReport { country_code } if !is_worldwide_code(country_code) => {
            Some(country_code)                      // ← 全世界コードのときは None
        }
        _ => None,
    }
}
```

ゴールデンコーパス（判定の回帰テスト集）でも期待値が反転しています。`visibility-filtering/rules/golden_corpus.rs:565-574`：
```rust
name: "legal_takedown_copyright_code_allows_without_viewer_country",
candidate: takedown_candidate(TakedownReason::LegalRequest { country_code: "xy".to_string() }),
expected_action: Allow,          // 旧: Drop
expected_decided_by: None,
```
`visibility-filtering/rules/golden_corpus.rs:594-603`：
```rust
name: "local_laws_takedown_worldwide_allows_any_viewer",
candidate: takedown_candidate(TakedownReason::BystanderReport { country_code: "xx".to_string() }),
expected_action: Allow,          // 旧: Drop(FilteredReason::UnspecifiedReason)
expected_decided_by: None,
```

**変わらないもの（重要）**

- **本物の DMCA**：`TakedownReason::Dmca` は引き続き `xy` を返すため、**全世界非表示のまま**（`golden_corpus.rs` の `dmca_takedown_drops_for_any_viewer` は変更なし）。
- **理由未指定 × `xx` / `xy`**：`UnspecifiedReason` は例外の対象外なので、**引き続き全世界非表示**（新規テスト `unspecified_takedown_worldwide_drops_without_viewer_country` / `..._copyright_code_drops_...` が追加され、明示的に固定されました）。
- **国を指定した法的要請**（例：`de`）：**その国の閲覧者にだけ非表示**、従来通り。

**Xユーザー／クリエイターへの影響**

- **影響を受けるのは「理由の付け方がイレギュラーだった記録」に限られます。** 「法的要請なのに国コードが著作権用の `xy`」「第三者通報なのに国コードが全世界」という、**記録の付け方の不整合で世界中から見えなくなっていた投稿**が可視に戻ります。
- **第三者通報（BystanderReport）は今後「国を指定したものだけ」が効きます。** 通報ベースで全世界から消す経路が閉じたことになり、**通報の乱用による広域の巻き添えが起きにくくなる**方向です。
- **既に非表示になっている過去投稿が遡って復活するかは、この差分からは判断できません（要確認）**。判定はリクエストごとに都度評価されるため、**理屈上は次回の表示時から効く**はずですが、上位のキャッシュ層の挙動までは本コードの範囲外です。

### 6. Grox 動画「モーションリビール」解析の誤検知対策（影響度：**小**）

**メカニズム**

前回（9/11）強化された、動画から静止背景を差し引いて「動いている部分」を抽出する解析の**精度チューニング**です。安全性審査フロー `grox/flows/ptos/task_special_video_screen.py` が、この解析でヒットした動画を審査対象に回します。

```python

_MOTION_REVEAL_MAX_WARP_LINEAR = 0.15
```
